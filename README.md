# 鲸伴 · 桌面陪伴助手

软件正式名称为「鲸伴」，默认角色仍为鲸鱼娘。为继续读取已有设置、凭据、聊天与配对记录，配置目录和内部通信标识沿用原有值。

当前开发版本为 Windows **1.1.0**、Android **1.20.0**。Agent 已改为直接运行官方 DeepSeek Harness SDK：工具选择、执行循环、上下文整理和会话恢复交给 DSH；Windows 电脑操控接入官方 CUA 源码。桌宠、聊天、角色卡、手机连接及文件下载继续使用鲸伴界面。实现和版本边界见 [Agent 说明](docs/ON_DEMAND_AGENT.md)。安装包完成验证前，下面的已发布版本仍为 1.0.2。

Windows **1.0.2** 的「鲸伴安装.exe」和「鲸伴.zip」位于 [下载页](https://github.com/Dove-666/JingBan-Desktop-Agent/releases/tag/v1.0.2)。无需安装 Python、Node 或项目依赖；首次使用自行配置聊天 API。分发包包含角色素材、本地棋类引擎、独立后台运行时和第三方许可，不包含开发者的设置、聊天、配对信息或密钥。详见[Windows 封装与测试说明](docs/WINDOWS_RELEASE.md)。

## 历史更新

以下记录描述各版本当时的实现和验证。旧安装包与临时原始报告已按用户要求清理，当前证据以[验证记录](docs/RELEASE_VALIDATION.md)为准。

R29 / Windows Beta.4 与安卓 1.16.0 将思考参数改为按接口、模型和明确能力声明适配：分别提供档位、开关或 Token 预算；不再给每个模型展示同一组八档。未知网关和模型别名默认不发送参数，可以在高级设置选择兼容方式或自定义供应商原值。桌面按接口和模型保存选择，切换后恢复；手机表单保留各模型的本次编辑草稿。电脑聊天、Agent 与手机直连使用同一份能力目录和对应实际参数，默认省略字段，不因不支持而自动重试。旧参数保留原语义，编辑表单展示当前模型的选项，保存后应用。现有传输仍是 OpenAI 兼容 Chat Completions，Claude 高级模式是明确的兼容网关转发配置，不代表新增原生 Messages 接口。实现参考 [CC Switch 的能力声明](https://github.com/farion1231/cc-switch/blob/e1f8acf6479068b05e7e9df7c764aff3f76c08b4/src-tauri/src/proxy/providers/codex.rs)，原始规则与官方文档链接保存在 `shared/reasoning/profiles.json`。本轮[验证记录](artifacts/user-testing-20261107-model-reasoning/verification.json)保留各次失败与最终通过的范围。

R28 / Windows Beta.3 按新默认参数封装：角色大小 100%；屏幕观察和远程发送开启，陪伴评论；观察 10 秒、分析 30 秒、变化阈值 0.08、发言冷却 30 秒、每小时 30 次、空闲暂停 585 秒。摄像头仍独立关闭，已保存配置保留。已逐项对照并重新封装当前气泡、聊天、角色同步和小屏棋局代码，见[本轮封装验证](artifacts/user-testing-20261107-defaults-release/verification.json)。

R27 与安卓 1.15.0 将当前角色独立于 API 配置同步：手机使用自己的模型时也跟随电脑所选角色，离线保留最后同步设定。在手机「连接与外观」可开启「电脑任务完成提醒」，仅活跃任务维持后台同步，任务结束提醒并停止服务。两种棋局适配 800×440 等小工作区，保留草稿、拖动、圆角和聊天阅读位置。本轮[验证记录](artifacts/user-testing-20261107-sync-background-games/verification.json)区分单元测试、原生系统测试和实体手机尚未验证的范围。

R26 增加本地角色库。打开“设置 → 角色 → 角色卡”，导入后点击“保存到角色库”；之后从已保存角色中选择并点击“切换角色”，无需再次寻找原文件。支持重命名库中的名称和删除条目，同一份设定不会重复收藏，重启后仍可使用。保存、重命名或删除库条目不会改写聊天记录；正在生成的回复保留原角色快照，切换后的新请求使用所选角色。删除库条目后，当前使用的角色仍保留，直到主动切换或恢复鲸鱼娘。手机使用电脑同步的模型配置时沿用当前已应用角色。

R25 补充独立的只读画面观察：Agent 可通过 `desktop_view` 获取当前可见画面的事实描述，调用使用主模型的图片能力，不启动鼠标键盘操作循环，也不以描述代替任务完成验收。成功观察或更新计划不再清除其它操作的失败链，未完成的视觉子任务按失败反馈给父 Agent。实际抖音任务仍需重新验收，当前不能据此承诺点赞任务已修复。

当时版本为桌面 `1.0.0`、安卓 `1.19.0`。Agent 支持原生工具、窗口控件和视觉操作在同一任务中接力，失败后可根据新观察修正方案；每个动作独立识别，结果未知时禁止盲目重放。手机新任务可由电脑确认排队后串行执行，重复请求保持同一任务，启动前失败和真实进程收束分别核验。长任务保留可回读的事实与来源，并在模型超窗后压缩请求继续；默认仍不限步数与总时长，保留停止操作。实现借鉴并移植了 [DeepSeek Harness 的计划机制](third_party/deepseek_harness/README.md)，沿用 Python/PySide6、nanobot 和 UI-TARS。详细范围与边界见 [Agent 说明](docs/ON_DEMAND_AGENT.md)和[可靠性验收](docs/AGENT_RELIABILITY.md)。源码启动的版本更新后须保存草稿、从系统托盘完整退出桌宠再启动；独立安装版须更新 Windows 安装包。

R24 增加酒馆角色卡。打开“设置 → 角色 → 角色卡”，导入 PNG 或 JSON，预览后点击“应用角色”，也可恢复默认鲸鱼娘。兼容 V1、[V2](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md) 和 [V3](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md) 的基础人设，使用名称、背景、性格、场景、示例对话及角色指令构造提示。开场白与作者备注可在预览中查看。世界书、扩展和素材引用保留为卡片数据，界面会显示兼容范围。

角色设定用于桌面聊天、电脑 Agent 表达、屏幕与摄像头评论，以及象棋对话。每次请求捕获当前角色，进行中的回复沿用该快照。使用电脑同步模型配置的手机会通过现有加密配置同步获得同一人设，手机手动 API 配置下的独立人设同步仍待接入。角色资料本地保存，模型请求沿用当前 API 配置。

桌面图片库可在“设置 → 常规 → 图片存储”查看用量并逐张管理。删除前显示已存档引用数量并再次核对引用关系；清理电脑副本保留聊天文字，手机缓存可能仍保留。正在使用的图片和未结束的任务会阻止清理，容量仍为 64 MiB。[图片管理与实际窗口验收](docs/qa-image-storage-manager-20261106.md)

R22 还修正了排队任务的无效重试与重复指导，以及退出时已保存成功任务被误报中断的问题，减少记忆状态读取中的重复采样，并支持显式声明 GBK/GB18030 的网页。动画加载仅在单次调用内共享完全相同的 PNG，不改画面或时序；实际节省取决于素材，不代表所有场景都降低进程峰值。[状态反馈](docs/qa-state-feedback-20261106.md) · [任务完成状态](docs/qa-agent-completion-20261106.md) · [网页与动画检查](docs/qa-web-and-frame-loading-20261106.md)

执行过程更新已接入增量通道。2000 条历史、40 段上下文的受控窗口样本中，20 次更新约 29.5 MB 降到约 1.5 MB，正文、阅读位置和草稿均保留。回复保存后确认返回异常也会先核对实际存档，恢复准确结果。[进度与保存恢复验收](docs/qa-state-feedback-20261106.md#保存确认与进度更新的后续验收)

R21 增加主聊天[粘贴图片与拖入聊天区](docs/qa-image-input-20261106.md)，先预览、再手动发送，并隔离读取期间的会话切换、清空和网页重载。文件交付可显示中文与 emoji 长文件名，保存失败可重试，约 16 MB 样本的整文件读取从 64 次减至 1 次，详见[文件保存检查](docs/qa-artifact-save-20261106.md)。图片准备和错误按会话显示，[后台导入时其它对话仍可发文字](docs/qa-image-staging-20261106.md)。电脑桥接异常与缓存也会保留派发状态，[未知输入不会因回执错误被误标成未派发](docs/qa-gui-effect-settlement-20261106.md)。纯文件目标在可选桌面观察失败后的自动恢复仍有两项明确未完成，当前未放宽目标验收。

R19 补齐 ZIP 完整流校验、深路径内存优化和跨端一致的 ZIP 文件类型；修正压缩包内部文件被误当成目录输出的验收问题。删除记录结果不明后，只有用户重新打开并成功读回真实记录，才能恢复发送；不会自动重删。受限项目计算的固定代码交付链已单独验证，但同一执行环境内仍存在上层进程访问缺口，通用 Python/终端继续关闭，真实模型代码未启用。当前执行程序使用核验签名与哈希的稳定私有副本，避免被桌面应用更新移除。

R18 接入了受限的只读资料子任务、独立文档渲染及页面核对，并为已认证手机队列补充宿主崩溃后的进程收束。真实模型已分别完成资料汇总和中文 DOCX/PDF 简报任务，失败记录及验证范围见可靠性验收。聊天文字草稿现在按会话保存在本机，重开窗口和切换面板会恢复，发送后的新输入不会被旧回复清掉；详见 [本机草稿](docs/LOCAL_CHAT_DRAFTS.md)。受限项目计算仍在修复隔离边界，通用 Python/终端未启用；正在运行的旧进程不会自动加载这些源码变化。

本轮加入原始目标与实际文件内容的独立验收、桌面及手机逐段回复、可停止的部分回复、跨端上下文引用，以及不接触宿主文件或网络的轻量 JavaScript 数据计算。验收任务、负例测试和真实模型结果分开保存；当前仍有未实现和未通过的任务，没有宣称已经等同 GPT Agent。手机 APK 使用原签名，覆盖安装保留原数据。

电脑和手机可按会话持续选择「电脑 Agent」，每条消息直接进入工具循环，不经过普通聊天分类器或关键词分派，也不要求先截图。工具目录共 42 项，按权限和实际依赖开放，受限项目计算在本机仍关闭。涵盖分页读写与局部编辑、PDF/Office 内容读写、Decimal/CSV 核算、网页搜索与匿名浏览器、只读系统检查、应用与窗口控件、视觉操作和结果验收；不提供任意 shell。外部文件或目录需要用户批准精确读写范围，不能由模型扩大授权。任务运行中可直接答复问题或补充指令，已验收文件可保存到电脑或手机。默认文件范围为 `agent_workspace/`，无需另开常驻网关。

较早实际模型验证了两轮文件创建/读回/修改，以及临时界面中的文字输入、点击保存与独立视觉验收。DOCX/XLSX/PPTX 生成、重新读取及手机交付通过测试；该批次的本机 Microsoft Office 启动故障仍保留在 [升级验收报告](artifacts/agent-upgrade-20261102/report.html)。后续独立 LibreOffice 路径已验证固定样例和中文 DOCX/PDF 真实任务，详见 [可靠性验收](docs/AGENT_RELIABILITY.md)。匿名浏览器不继承用户登录，副屏操作仍明确未支持。

聊天左下角的「设置」现为同窗页面：左侧选择常规、角色、模型与 API、屏幕感知、摄像头、长期记忆或远程连接，右侧直接编辑。返回聊天保留原会话与未发送草稿，密钥仍由原生控件及系统凭据管理。桌宠右键和托盘也使用此设置页，开发用的 `--debug-panel` 入口保留。

## Windows 安装与启动

需要 64 位 Python 3.10 或更新的受支持版本。本机已建立 `.venv` 并安装依赖，实测环境为 Python 3.10.11、PySide6 6.12.0。

首次安装（PowerShell，在项目目录执行）：

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 可选：需要 Mem0 长期记忆时安装
.\.venv\Scripts\python.exe -m pip install -r requirements-memory.txt

# 可选：在本机运行中文 Embedding，无需 Embedding API Key
.\.venv\Scripts\python.exe -m pip install -r requirements-memory-local.txt
```

如果没有 Python 3.10，可将第一行换为 `python -m venv .venv`，使用已有的 Python 3.10+。项目使用明确的虚拟环境路径，无需执行 `Activate.ps1` 或修改 PowerShell 执行策略。

正常启动：

```powershell
.\.venv\Scripts\python.exe main.py

# 启动时同时打开调试面板
.\.venv\Scripts\python.exe main.py --debug-panel
```

也可以双击 `start_pet.bat`，通过虚拟环境的 `pythonw.exe` 启动，不保留控制台。排查启动问题时使用上面的控制台命令。

在聊天左下角「设置 → 常规 → 启动」调整开机自启动与开机时静默启动。开机自启动仅注册当前 Windows 用户的鲸伴启动项，不需要管理员权限；取消勾选会移除这一项。开机时静默启动只保留系统托盘图标：双击打开聊天，右键可显示桌宠、打开设置或退出。若 Windows 托盘不可用，会自动显示桌宠。开关默认保持关闭，更改在下次自动启动时生效；手动打开程序始终显示桌宠，已有实例时也会恢复显示。

临时只启动到托盘可运行 `start_pet.bat --silent`。`--debug-panel` 明确要求显示调试窗口，优先于静默偏好。Windows 自启动使用项目的绝对路径；移动项目目录后，应在新位置重新关闭、开启自启动。

「设置 → 模型与 API」提供思考强度：默认、关闭、极低、低、中、高、很高、最高。选择后点击「保存配置」，从下一次请求生效；「默认」不发送额外推理参数，保留服务商默认行为。其他档位使用 Chat Completions 的 `reasoning_effort`，支持范围取决于模型；不支持时会显示明确错误，不会自动重试或悄悄降级。较高强度可能增加等待时间与输出预算消耗，可在「常规 → 上下文预算」调整输出预留。参数依据 [OpenAI Docs](https://developers.openai.com/api/docs/guides/reasoning?api-mode=chat)。

「设置 → 模型与 API」的「获取模型列表」会使用当前填写的 Base URL 和密钥（密钥留空则沿用已保存的密钥），在后台查询服务商的模型列表。无需先填模型名称；获取后可下拉选择、输入关键词筛选，也可继续手动填写。获取不会替换当前模型或自动保存，选择后点击「保存配置」生效。地址或密钥变化会清除旧选项并忽略迟到结果；不支持模型列表的服务商仍可手动配置。查询使用 [OpenAI Docs 的模型列表接口](https://developers.openai.com/api/reference/resources/models/methods/list)，不会发送聊天内容；列表中的模型能否聊天或识图仍需单独验证。

只读诊断不会启动桌宠、读取配置/凭据/聊天或联网，即使 PySide6 缺失也能打印依赖问题：

## 使用与调整

- 左键按住角色拖动；超过系统拖动阈值后视为拖动，松开不会触发对话。
- 启动后自动轻微上下浮动并呼吸。短按交替触发开心、惊讶弹跳与气泡，并打开独立聊天窗口；普通点击反馈默认 3 秒后隐藏。
- 正常、惊讶、困倦、生气、思考和说话表情支持眼睛平滑跟随鼠标，开心表情保留闭眼效果。右键角色可切换“眼睛跟随鼠标”，该开关在表情切换后继续生效，只影响本次运行。拖动与恢复时冻结视线，视频动作使用自己的画面。每种表情的独立分层素材位于 `assets/character/eyes/`；单套素材缺失、损坏或与原表情不匹配时，该表情自动使用静态图。
- 按下即冻结当前动画姿态，拖动时由鼠标控制窗口；松开后平滑恢复待机。气泡不会阻挡拖动。
- 右键角色，选择“退出桌宠”。关闭时停止定时器并退出进程。
- 右键可打开“设置”或“打开聊天窗口”；设置和聊天共用同一个窗口，关闭窗口后桌宠和当前会话继续运行。
- 聊天侧栏支持新建、搜索和打开历史会话；每条会话的菜单提供查找、导出、重命名、清空与删除。重启默认空上下文，旧记录继续保留；打开历史后可继续该会话。“长期记忆”和“上下文预算”统一位于设置页，记忆默认关闭；开启「自动记忆」后程序为新用户准备本地中文模型并复用聊天服务，页面只保留开关和记忆管理，已有配置与记忆保留。
- 「设置 → 模型与 API」配置聊天服务；会话菜单的「导出对话」可保存完整 Markdown / JSON，包含正式屏幕评论及文字情境，不包含配置、内部 metadata 或截图。
- 发送时底部显示实际保存、记忆检索、生成和保存回复阶段；切换会话不会将旧请求的阶段或回复归给新会话。草稿和阅读位置分别保留。
- “设置 → 角色”支持 50%～200% 实时大小调整并保存，提供七种逻辑表情；缺少独立 PNG 时会明确提示，并使用原图、动作或气泡反馈。
- “屏幕感知”选项卡可单独启用本地观察和远程分析。默认每 10 秒本地观察；只有画面变化、权限允许且满足间隔和去重条件时才调用模型。点击“3 秒后本地观察”后切到目标应用，采集后返回面板查看；此按钮始终不外发。返回鲸伴时保留并标记上次安全预览，自身窗口不截图。
- “互动风格”默认“陪伴评论”：清晰的 `media` / `interesting` 情境在置信度至少 0.60、重要度至少 0.10 且有候选回复时可自动评论。“只在重要时说话”保留 0.65 重要度门槛；`none` 或无有效画面仍保持安静。修改后点击“保存参数”。
- “评论当前画面”将最近一次安全预览发给已配置 API，不新截图；需要本地观察和远程发送均已启用并保存。可以返回鲸伴面板查看旧预览后点击；此明确请求不受自动重要度、去重、发言冷却和配额限制，也不消耗或重置自动发言计数。隐私/未知窗口、其他窗口切换、禁用、请求占用或拖动仍会阻止或取消评论；错误时显示实际错误，不生成伪评论。
- 自动主动反馈支持安静、只动作和气泡发言，默认发言间隔至少 30 秒、每小时最多 30 次；聊天和拖动优先，未配置 API 仍可使用桌宠与本地观察。它不会评论每一帧视频。
- 透明空白和 PNG 的透明孔洞可以点击后面的软件；角色本体是鼠标交互区域。
- 桌宠置顶但不抢走键盘焦点、不显示任务栏按钮；整个窗口被限制在可用工作区中。Windows 自动隐藏任务栏的区域也会预留。

窗口和角色尺寸使用 Qt 逻辑像素；实际显示会跟随 Windows 的缩放比例。角色以窗口中心为基准按比例绘制，布局为气泡、最大弹跳和呼吸预留空间，因此 `--character-size` 是最大边长。超大自定义动作会被限制在可绘区域中，避免角色移出窗口；超过屏幕工作区的窗口也会自动缩小。

```powershell
# 调整窗口、角色和气泡时长
.\.venv\Scripts\python.exe main.py --width 420 --height 540 --character-size 400 --bubble-seconds 4

# 替换素材；带空格的路径需要引号
.\.venv\Scripts\python.exe main.py --image "E:\素材\我的角色.png"

# 查看全部参数，包括动画帧率 --fps（默认 30，范围 1–120）
.\.venv\Scripts\python.exe main.py --help
```

窗口设置位于 `desktop_pet/config.py`，动画参数集中在 `desktop_pet/animation_config.py`。默认图片是 `assets/whale.png`，由原有透明 PNG 原样复制，没有重绘角色。从其他工作目录启动也能找到默认图片；自定义的相对 `--image` 路径则相对当前终端目录。

## 动画状态与扩展接口

| 状态 | 行为与切换 |
| --- | --- |
| `idle` | 上下浮动 ±2.5 px，周期 4.8 秒；叠加 0.996–1.004 的轻微呼吸缩放，周期 3.8 秒。 |
| `happy` | 快速上跳约 12 px，再缓慢回落，总长 0.55 秒，完成后回到 `idle`。 |
| `surprised` | 短暂上跳约 7 px，总长 0.35 秒，完成后回到 `idle`。 |
| `dragging` | 最高优先级；按下时冻结当前位移、缩放和待机相位，鼠标只移动窗口，期间拒绝动作触发。 |
| `returning` | 拖动松开后用 0.4 秒平滑衔接到待机，完成后回到 `idle`。 |

呼吸是姿态的一部分，无需单独抢占状态。短按松开时交替触发 `happy` / `surprised`；用户动作可以打断正在播放的动作或恢复过程，并从当前姿态衔接。重复触发不累加位移，拖出再返回仍算拖动。

原始鲸鱼娘安静待机 4～7 秒后，会从 8 个 `idle_` 动作和姿态中随机播放一轮，之后间隔 8～16 秒再换动作，不会连续重复。其中「傲娇抱臂」复用现有静态 PNG，平滑淡入后停留约 2 秒，再淡回普通待机，保留呼吸效果；没有重新生成视频或新增 API 表情。聊天请求、回复气泡阅读、拖拽、隐藏桌宠以及手动动作预览期间暂停随机播放；对话中的表情沿用 API 语境选择。3 秒内连续点耳朵或尾巴 3 次（可交替点击），会短暂生气约 8 秒，继续点击不会无限延长；到时恢复待机，若正在读新回复则先恢复该回复的表情。自定义图片和另选的固定静态角色不使用鲸鱼娘的随机动作素材。

`AnimationController` 不处理窗口、图片或磁盘 I/O，只输出不可变的 `AnimationPose(offset_y, scale)` 和 `AnimationState`。现有的唯一帧 `QTimer` 用实际经过的秒数调用 `advance(dt)`；绘制与鼠标命中共享变换，旧位置每帧清为真实透明。原图、缩放图和透明命中数据均缓存，不在每帧重读或重建。

后续素材渲染器可通过 `PetWindow.animation.state`、`.pose`、`frame_tick` 接口选择帧或部件，继续复用当前时钟和鼠标交互。本阶段不实现眨眼、嘴型或鱼尾摆动。

## 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 提示缺少 PySide6 | 使用 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`，并用同一个解释器启动。 |
| 提示找不到图片 | 恢复默认 PNG，或用 `--image "完整路径.png"` 指定文件；界面会显示具体路径，控制台同时输出错误，确认后退出码为 2。 |
| 图片存在却读不出 | 确认文件为有效图片，而不是仅修改了扩展名；错误框会包含 Qt 的读取原因。 |
| 角色有白底 | 检查是否误选了原始 JPG，使用已抠图的透明 PNG。 |
| 角色太大或太小 | 调整 `--character-size`；同时增大 `--width`、`--height` 可提供更多空间。 |
| 想减弱动作或降低刷新率 | 调整 `animation_config.py` 的位移/呼吸幅度；也可启动时传 `--fps 24`。 |
| 双击启动器没有显示 | 用控制台启动命令查看报错；先确认 `.venv` 和依赖已安装。 |
| 感知没有预览/发言 | 查看“屏幕感知”状态，确认开关已保存；自身窗口、隐私过滤、空闲、稳定画面、请求间隔和发言配额均会跳过。 |
| 有分析结果却不评论 | 查看分类、候选评论和中文原因；`none` 或空回复不能发言。普通视频选择“陪伴评论”并保存；立即测试可检查安全预览后点“评论当前画面”，该按钮会发起真实 API 请求。 |
| 返回面板只看到旧预览 | 鲸伴在前台时不观察自身；点击“3 秒后本地观察”并及时切换目标应用。上次安全预览会明确标记。 |
| 无法确认是否运行新版 | 查看面板右上角和标题栏 `2026.11.03-r18`；旧进程不会热加载源码，需正常退出后从本仓库启动。 |
| 启动故障但不想打开窗口或暴露配置 | 运行 `python -m desktop_pet.diagnostics --json`，只查依赖和资源，不读凭据、聊天或屏幕。 |
| 想使用记忆但不懂模型配置 | 安装 `requirements-memory-local.txt` 后，在「设置 → 长期记忆」开启「自动记忆」；新用户的本地检索模型由程序准备，提炼复用聊天服务。 |
| 想保存一段历史 | 打开该会话，再用“工具 → 导出当前对话”；导出不受近期上下文条数限制，取消不会创建文件。 |
| 预览近全黑或有灰块 | 近全黑会在本地拒绝，不请求模型；灰块是其他窗口遮挡的遮蔽区域。将目标窗口保持可见后重试，受保护内容不会绕过采集限制。 |
| 聊天正常但图片分析失败 | 模型还需支持 `chat/completions` 的图片输入；文本连接成功不能证明视觉能力。 |
| 想退出 | 在角色不透明部分右键选择“退出桌宠”。 |

实现所依据的窗口行为可查阅 [Qt 透明 QWidget](https://doc.qt.io/qt-6/qwidget.html#creating-translucent-windows)、[Qt 屏幕工作区](https://doc.qt.io/qt-6/qscreen.html#availableGeometry-prop) 和 [Microsoft 任务栏位置查询](https://learn.microsoft.com/en-us/windows/win32/shell/abm-gettaskbarpos)。
