# 鲸伴 安卓伴侣

手机可独立调用模型进行文字和图片对话，也可连接运行中的鲸伴，通过持续的「电脑 Agent」模式使用电脑已启用的实际工具并同步对话。配对后自动同步电脑的 API 配置；未配对时也能在设置中填写自己的接口和密钥。当前版本为 1.19.1，versionCode 为 27。

## 安装与配对

1. 安装 `deliverables` 中的 `1.19.1/鲸伴.apk`（或同目录的通用架构包）。普通近年安卓手机优先选 `arm64-v8a`；不确定处理器时选 `universal`。最低 Android 8.0。
2. 只在手机聊天：在欢迎页选择「配置模型」，或从右上角「设置 → 模型与 API → 编辑」进入配置，填写 HTTPS API 地址、模型名称和 API Key。手机联网即可对话，不需要先配对电脑。若需自动同步电脑配置及聊天记录，继续以下步骤。
3. 电脑安装远程组件：在项目根目录运行 `.venv\Scripts\python.exe -m pip install -r requirements-remote.txt`，然后启动桌宠。更新源码后须先从系统托盘选择退出，再重新启动；仅关闭聊天窗口不会加载新代码。
4. 在电脑的「控制台 → 远程连接」或托盘「手机远程连接」中开启功能，生成并复制配对信息。
5. 在手机欢迎页点击「连接电脑」，或在右上角设置中连接，粘贴完整配对信息并确认。内容应是 `aura://pair/` 开头的长链接或完整 JSON，不能只输入短配对码。配对信息五分钟内有效，只能使用一次；之后由设备密钥自动认证。

1.19.1 使用原签名，可覆盖安装同签名旧版，无需卸载或清除数据。持续「电脑 Agent」、手机独立聊天、静默同步及短暂后台连接复用继续保留。电脑源码启动的版本更新后须从托盘退出旧进程再启动；独立安装版须更新 Windows 安装包。更换手机或电脑账号时仍需相应配对和权限，升级不会自动扩大授权。

首次配对、从电脑同步 API 配置、同步记录和控制桌宠时，电脑需要运行且联网。手机聊天只需要手机能访问模型 API；电脑可以关机。记录保存在本机，重连电脑后同步；未配对时创建的手机记录会在首次主动配对后同步到所选电脑。手机可以用移动网络，电脑可以用家中 Wi-Fi。设备通信优先尝试直连，无法直连时使用 iroh 提供的公共中继；不需要自行租服务器。公共网络和中继的可达性会影响设备同步成功率及延迟。

## 对话与同步

- 首次连接下载电脑的会话和消息，之后同步变化。历史保存在手机 SQLite 数据库，离线仍可阅读。
- 聊天页的自动同步静默进行，连接状态和手动同步入口位于「连接与外观」。常规自动重连失败不反复弹消息；主动操作失败及授权失效仍给出提示。
- 本地配对信息读完后立即尝试连接，移除旧版启动时可能多等的 2 秒。没有开启任务提醒或没有电脑任务时，切到后台停止轮询，保留现有连接 45 秒供短暂切换复用；有任务且开启提醒时，使用有系统通知的临时前台服务继续同步，结束后退出。
- 空闲时约每 10 秒增量同步，有待发内容或正在等待回复时约每 2 秒检查；API 配置自动检查间隔 30 秒。手动同步、配对和重新连接会立即检查配置。相同配置不重复加密写盘，空同步不重读整份历史。
- 「手机聊天」有可用的缓存 API 配置时，手机直接请求模型，保存用户消息和回复，再把完整记录同步到电脑。图片也直接发送给模型，不必等待图片先传到电脑；「电脑 Agent」始终提交电脑工具后端。
- 电脑端更改 Base URL、模型、密钥或思考强度后，手机在前台连接同步时自动更新。密钥通过已授权的加密设备连接传输，在手机使用 Android Keystore 加密保存，不写入聊天数据库或日志，也不显示明文。
- 手机直连使用 HTTPS 接口，手机网络也必须能访问这个地址。电脑专用的 `localhost` 或 `127.0.0.1` 地址不能用于手机访问电脑上的服务。
- API 请求失败、超时或结果不确定时，不自动换电脑重新调用模型。界面保留消息和失败状态，由用户决定后续处理，避免重复付费请求。
- 没有可用 API 配置时保留输入和待发图片，显示模型配置入口，不再为新聊天静默创建电脑转发队列。旧版未尝试发送的待发消息可明确选择「手机直接发送」，保留原图片和消息身份；已经尝试投递、状态不确定的消息须先确认原操作，不能直接再次调用模型。
- 电脑删除的会话会同步删除。属于已删除会话或另一台电脑的待发内容保留供手动处理，不会悄悄投递到新会话。
- 手机与电脑的聊天使用同一会话记录；手机生成的回复导入电脑时只保存记录，不会再次调用 AI。两端不会为同一轮重复生成回复。
- 每次在内存中显示当前会话最近 500 条消息；完整同步记录保存在手机数据库。

## 图片与桌宠

系统选图器无需相册存储权限。图文发送流程如下：

1. 在聊天输入区选择图片，先检查待发送图片预览。选图后不会立即发送或调用模型，可移除后重选。
2. 输入想问的问题，也可以不写文字、只发图片。
3. 点击「发送」后，App 才会发送图文请求。「手机聊天」有 API 配置时直接向模型发送图片和问题，回复立即保存在手机，电脑离线不妨碍这一步；「电脑 Agent」的本次图片先上传电脑，再随任务提交。
4. 手机与电脑连接时同步图片及完整对话记录。电脑聊天中自动显示图片缩略图，点击图片可放大查看；旧聊天里的有效图片也会自动显示。旧电脑转发模式仍按先上传图片、再请求电脑模型的顺序执行。

文字消息不会自动附上以前的图片。明确追问“上面这张图里写了什么”时，只在原来的历史图片消息中提供图片上下文，当前文字消息保持纯文字；新话题和单独的问号不重新携带旧图。图片上下文限于当前会话近期仍可读取的图片。以前只传进电脑收件箱、没有作为图文消息发送的图片，需要重新选择并点击「发送」，之后才能识图和追问。

手机会先缩小相机原图；单张传输上限 4 MiB，支持静态 PNG/JPEG/WebP，图片缓存上限 64 MiB。聊天记录保存图片引用，手机按需读取图片。原图已删除、校验失败或模型接口拒收时会显示明确提示；需要重新选图，或检查电脑模型是否支持图片及接口配置。

桌宠控制包括表情、缩放、显示/隐藏和说一句话。动作只在连接时发送，离线不会排队重放。

## 电脑 Agent

手机输入区选择「电脑 Agent」后发送消息。模式随当前会话保存，发送后和重开会话时均保持；切换会话使用该会话自己的模式。“继续”“修改刚才的文件”等后续消息直接进入同一电脑 Agent 会话，不要求重复动作关键词。选择模式本身不会执行。切回「手机聊天」后，普通对话继续直接使用手机模型。

手机通过 `agent.send` 把会话 UUID、原始文字及可选的本次图片交给电脑，与电脑聊天使用相同的 ChatController、AgentService 和 nanobot 原生工具循环。不经过普通聊天分类器、情绪 JSON 或单轮截图分派。电脑离线时保留输入，不创建以后自动执行的任务，也不会把 Agent 请求改成手机普通回答；响应不确定时只查询原请求，防止重复执行或重复模型计费。

按电脑已保存的权限，Agent 可组合工作区文件读写和查找、公开网页读取、只读系统信息、应用目录查找、使用当前候选 ID 打开应用，以及截图、原生窗口工具和视觉操作。新增文件授权仅由当前任务中的明确操作授予指定路径和读写范围，不接受模型自造授权。文档工具可以生成并回读文件内容；文档渲染、GUI 操作及最终视觉核验依赖相应本地环境。匿名浏览器使用独立临时资料，不继承用户现有浏览器的登录状态，只接受公开 HTTP(S) 目标。没有任意 shell。实际范围见[桌面 Agent 说明](../docs/ON_DEMAND_AGENT.md#实际工具范围)。工具记录和可回读观察按会话及权限隔离；中断或重启不自动重放已派发操作。清空会话及更换账号、工作区或授权范围仍受隔离与删除规则约束。

任务运行时显示固定的公开阶段、工具动作标签和安全错误，可点击「停止电脑任务」，通过 `agent.cancel` 停止当前会话任务。停止和超时不会回滚已经完成的文件写入或电脑动作，也不会自动重放任务。

Agent 开始前不强制截图，文件和网页任务不依赖屏幕感知开关或电脑前台停在哪个窗口。需要电脑操作时，在电脑「设置 → 任务助手」启用对应能力，并配置聊天模型、GUI 视觉模型、独立 GUI 密钥和本地运行组件；配对与选择模式不会自动开启权限。顶部更多菜单中的「查看电脑桌面」独立请求一次符合屏幕感知授权、暂停状态和隐私规则的前台图片，不调用模型；该截图入口失败不会阻断其它 Agent 工具。

1.7.0 新增 Windows 只读 `inspect_system`、`inspect_disk_usage` 和 `inspect_directory`。可读取实际内存和固定本地盘总量、已用与可用空间，检查已知临时目录、下载和回收站等分类的有界大小，或列出本地目录名称、类型和大小；不读取文件内容，不执行清理、删除或任意 shell。文本写入仍限于工作区。磁盘检查采用 6 秒扫描预算和条目上限，权限不足或超出预算时返回部分结果；未知值保留未知，逻辑大小不等于已承诺可回收空间。Windows 系统缓存应通过系统存储设置处理，不自动删除。

本次 C 盘任务的存档执行元数据显示，旧路径先读工作区系统信息，再执行 9 次 GUI 动作，约 123 秒后触发原有 120 秒总超时；这是实际执行后的超时，不能归为截图失败或没有进入 Agent。新增只读工具让系统/磁盘问题可优先读取结构化数据。GUI 工具启动时只领取剩余总时间，并预留 10 秒用于终止与整理结果；时间不足时不派发新操作，不自动重放动作。同步内部 schema 6 更新旧消息投影触发器，使「检查电脑状态」「检查磁盘占用」「查看目录信息」等白名单标签传到手机，不发送工具参数或私有路径。

Windows 电脑操作截图优先采用原生 Win32 采集，将物理图片尺寸与鼠标输入的 DPI 坐标对齐；采集失败时仅做有界截图回退，不重放模型请求、点击、输入或整项任务。锁屏或安全桌面、断开的桌面会话、显示器不可用/切换和近乎全黑的画面分别显示明确错误。请先在电脑恢复桌面，再根据当前实际状态发送新任务；助手不会自动解锁或确认 UAC。独立「查看电脑桌面」继续遵守原有前台窗口隐私规则。

可以显式选择本次图片，预览后随 Agent 任务发送；先以稳定上传请求保存图片，再发送引用该图片的 Agent 请求。选图本身不调用模型，后续未附新图的 Agent 消息不会自动再次携带旧图。电脑聊天输入区也保留加号选图、预览、移除和仅发图片。

## 本地构建

需要 JDK 17 或更新兼容版本、Android SDK 平台 35 和 Build Tools 35。项目使用 Gradle Wrapper，不需要安装 Android Studio。当前工作机的 SDK 位于 `E:\Android\Sdk`，JDK 位于 `E:\Biancheng`。

```powershell
cd E:\github\AURA-Desktop-Agent\android
.\build-apk.ps1
```

构建脚本先运行单元测试及 Release Lint，再生成签名安装包。可用 `-SdkPath`、`-JdkPath` 和 `-SigningDirectory` 指定路径；`-SkipTests` 只适合已验证相同源码后的打包。

发布签名保存在项目外 `E:\Android\keys\aura-companion-release.p12`，密码使用当前 Windows 用户的 DPAPI 加密保存在同目录。后续更新 APK 必须保留同一签名。密钥和受保护凭据不要提交到仓库；DPAPI 凭据不能直接在另一 Windows 账号解密，迁移前应单独安全导出签名凭据。

设备身份由 Android Keystore 保护；不保存一次性配对码。手机应用关闭 Android 云备份和设备迁移备份。电脑可随时撤销手机授权，撤销后手机需要手动重新配对。

UI 使用原生 Jetpack Compose 与系统字体，提供浅色、深色及跟随系统主题。1.6.0 的鲸鱼娘图标由内置图像生成工具参照项目角色制作；原图为 [`assets/branding/android/whale-maid-icon-v1.png`](../assets/branding/android/whale-maid-icon-v1.png)，生成说明为 [`icon-prompt.txt`](../assets/branding/android/icon-prompt.txt)，Android 资源使用其 512px 导出和原生渐变背景。测试用示例记录只位于 instrumentation 测试 APK，不会进入发布安装包。
