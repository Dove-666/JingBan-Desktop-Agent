# 手机聊天的上下文与停止边界

普通聊天优先使用手机独立 API，电脑不可用时也能生成。一次发送只调用一次模型，不因停止、断流、切换电脑或 API 设置而重发，不自动改由电脑再生成。

手机只把正常完成的完整一轮标记为 `ready`，再用固定消息 ID 的 `chat.import` 同步。SSE 要求显式 `finish_reason=stop` 和 `[DONE]`；兼容普通 JSON 也要求显式 stop，缺失/null/length/content_filter 不推定完成。停止、超时、断流和身份变化保留已接收的公开文字为 `unknown`；迟到的 callback/完成响应不能把它重新改成 ready，也不能创建替代请求。原生 HTTP 取消会关闭连接，非协作测试网关的迟到结果也会被拒绝。

活动回复预览绑定电脑身份、会话 ID、首条消息代次、direct turn ID、用户消息 ID、回复消息 ID，以及 API 来源/地址/模型/配置版本。切换对话仍可在原会话继续生成；更换电脑、API 或清空后的代次变化会停止原预览。历史摘要不是电脑操作授权。

同一代中的消息编辑、删除和状态变化也可能撤销摘要中的内容。因此所有同步消息/会话变更同事务删除该会话的 context cache，并更新本地 mutation epoch。`context.get` 在发起时捕获 epoch；返回后只可在电脑身份、代次、epoch 均未改变的同一数据库事务中缓存，防止旧 RPC 在删除后把摘要写回。关闭或不可用的记忆返回会整体替换旧条目。

已发给模型服务的请求内容无法撤回。这里保证的是本机发现变化后停止展示/继续接纳旧任务，并拒绝在后续请求或记录同步中复用失效摘要；不能保证撤销模型服务已经接收的内容。电脑离线时，手机也无法预先知道电脑上尚未同步的删除或记忆撤销。

当前和本进程已经观察到的 API 密钥在系统提示、历史引用、用户文字、标题、流式片段和最终回复进入边界时统一遮蔽。跨 chunk 的所有已知密钥前缀先暂存，不显示完整密钥。历史密钥的额外匹配集合只在 RAM 中供本次请求使用，不写入普通配置编码或日志；替换配置/移除电脑缓存时，已知旧密钥也先从保留的提示词中遮蔽。模型 API 的 Authorization 头仍只使用当前配置的实际密钥。

图片只能由当前输入框显式附件提供，或在用户明确指代历史图片时从原用户消息处回读一张有界图片。历史图片不会变成新用户消息附件；无关文字、切换会话及新图片不会自动携带之前的图片。

首条手机消息在持久化时生成有界本地主题，不增加模型请求。明确的电脑手工标题和有意义的同步标题优先；新电脑通过严格 JSON bool `title_manual=false` 标注自动占位标题时，手机可保留同代 fallback。老电脑缺少或错误编码该字段时，手机只为本机新建会话生成 fallback。

验证：`ChatBoundaryAuditTest` 使用合成记录、假电脑与可故意迟到的流式网关；`DirectStreamTest` 的本机 HTTP fixture 检查增量、关闭阻塞连接和不重发。它们不访问真实模型、不读取生产密钥，也不能替代最终 release 的实际界面验收。
