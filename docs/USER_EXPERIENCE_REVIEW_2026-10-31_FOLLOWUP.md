# 鲸伴桌宠使用体验复查 · 2026-10-31

本次重新测试当前仓库和正在运行的桌宠，并对照前一份审阅。只新增报告和审查证据，没有修改产品代码、现有测试或真实聊天/记忆数据。隔离测试使用临时配置、内存凭据、本地模型服务替身及真实 Mem0/Qdrant；没有调用外部模型 API。

使用者最需要的是：遇到问题能继续操作、能看懂鲸鱼娘的状态、能够确认和纠正她记住的事情。目前基本聊天、会话隔离、隐私开关和本地记忆持久化已有基础；以下问题更适合优先处理。

**本轮新增确认的问题与阅读建议：**

| 问题 | 实际表现、证据与建议 |
| --- | --- |
| 自定义角色会被默认表情覆盖 | 用 83×117 的合成透明 PNG 指定 `--image`，`PetWindow` 起初加载正确，构造 `PetController` 后却被 1024×1024 的项目 neutral 素材替换；界面仍称使用自定义图片。手动恢复 original 后，点击逻辑回调和真实隔离聊天控制器的情绪信号又会覆盖。位置：`pet_controller.py:50-51,108-110`。建议按所选角色决定表情来源，自定义角色缺素材时使用动作/气泡反馈，保持角色身份。证据：`perception/probe_current.json/new_custom_image_issue`。未操作用户原图。 |
| 明确改口后，新旧长期偏好同时进入新会话 | 两次本地模拟提炼分别返回“喜欢大字体”和更正后的“现在喜欢小字体，不再喜欢大字体”。真实 Mem0/Qdrant 最终保留两条，检索返回两条，新的会话上下文也同时注入两条，没有事实时间或替代标记。位置：`memory/worker.py:314`、`conversations/context.py:212,228`。建议提供可查看的事实来源、时间和替代/过期关系，检索优先当前有效偏好；管理页可支持编辑或纠正。证据：`chat_memory/memory_correction_observations.json`。这里确认的是存储与上下文歧义，未验证真实模型是否会因此回答错误。 |
| 小角色下的气泡字号偏小 | 审阅后段气泡有外部更新，新增独立探针确认：50% 角色时字体 6pt，75% 时 9pt，100% 时 12pt。建议提供独立的阅读字号和下限，不让缩小桌宠同时降低文字可读性。160 字样例的全文仍保留、两页都可到达，不能把分页误报为截断；可补悬停暂停和前后翻页以便慢读。证据：`updated_bubble_observations.json`。这是阅读偏好建议，不把新的比例缩放本身当作程序崩溃。 |

**上轮问题的当前复测结果：**

| 用户感受 | 当前状态及建议 |
| --- | --- |
| 问了却没回复，不知道怎么恢复 | 仍复现：A 会话后台失败后切回，数据库状态为 failed，页面没有失败标记/重试入口；重启后重试目标也无法恢复。缺 Key 时“重试”还会覆盖原本的配置指引。应按消息恢复失败状态，区分“打开设置”“重新读取”“重试回复”。 |
| 聊天页面坏了就无法继续使用 | 仍复现：对隔离 WebEngine 注入失败后，仅有重新加载，已有原生聊天 splitter 仍被隐藏。应增加兼容聊天入口并沿用现有会话和草稿。本轮没有让生产页面崩溃。 |
| 鲸鱼娘没有说话，却被算成说过了 | 仍复现：主动评论存储失败时，气泡为 0、发言次数为 1，事件已去重；推进 61 秒，另一个有效事件仍被冷却挡住。应区分生成、保存、呈现，在正确成功阶段提交计数，失败能够安全恢复。 |
| 某些动作仍不能视觉贴边 | 当前真实素材与 Qt 拖动事件复测：100% 大小的“趴下”首帧左侧余量约 37.6、右侧约 43.8 个逻辑像素；neutral 顶部约 17.3。稳定动画包围框贴边不等于当前人物轮廓贴边。建议拖动冻结帧按实际轮廓限制，松手后继续避免裁切和突然跳动。此次是离屏 Qt 事件实验，未进行物理鼠标四边测试。 |
| 记忆明明存在却找不到 | 仍复现：临时真实库有 1005 条，列表只返回 1000 条；遗漏记录按完整原文搜索为 0，但库中仍存在。应分页管理完整的当前用户命名空间，显示真实总量，保证每条能被定位和删除。 |
| 明明提示记住了，列表还是空的 | 仍复现：自动提炼状态报告更新 1 条，打开的列表仍为 0，手动刷新才出现。应自动刷新当前筛选，保留搜索词及选择。 |
| 回复里的链接不能用 | 实际打包页仍把链接渲染为没有 href/title 的 span，点击、键盘聚焦与复制目标都不可用。应通过原生层验证地址并在系统浏览器打开，提供复制链接，保留网页资源隔离。 |
| 历史会话标题相似时很难找 | 控制器已有日期、摘要和消息数，bridge 只给前端 ID/标题。同名会话在侧栏无法凭时间和概况区分。应补日期分组、更新时间和概况查看入口。 |
| 窄窗口用键盘操作历史时焦点不对 | 420×420 的抽屉打开后，实际 Qt Tab 仍进入遮罩后的新对话、工具、复制和输入框。应打开时聚焦抽屉、限制焦点，并在关闭后回到触发按钮。 |

**建议补齐的日常体验能力：**

- 阅读设置：标准/大字体、浅色/深色/跟随系统。当前聊天正文 14px，窄窗口降至 13px；这里不指已调整过的评论气泡。不同窗口的主题也应保持一致。
- 等待控制：增加“停止生成”，取消后正确处理迟到响应；显示请求属于哪个会话。当前编辑草稿正常，但请求结束前没有用户级停止入口。
- 感知状态：在聊天处显示当前是否观察、是否允许远程发送，并提供本次暂停；控制台显示剩余冷却、剩余次数和上次成功分析时间。现有托盘暂停、控制台恢复都已工作，不能说系统完全没有这些入口。
- 预览时效：在“上次预览”旁显示采集时间/年龄，提醒手动评论使用的是这张旧预览。当前已有“不是实时画面”说明。
- 日常设置：统一“设置/控制台/调试面板”命名，普通页面保留常用项，高级区域容纳素材路径、版本和调试参数；清除系统保存的 Key 增加确认。
