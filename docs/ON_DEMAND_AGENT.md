# 桌面 Agent 与手机接入

电脑操作现已增加 Windows 控件执行、动作后新截图与独立目标验收；执行模型说结束不再直接代表任务成功。详见 [结果确认机制与本轮边界](COMPUTER_CONTROL_VERIFICATION.md)。

电脑聊天窗口和手机都提供持续的“电脑 Agent”模式。每条新消息直接进入真正的 nanobot 原生工具调用循环：模型选择工具、收到工具结果、继续执行并返回自然语言结果。不经过普通聊天分类器、动作关键词、情绪 JSON 或 `agent_request` 路由字段。Agent 可以直接回答问题，不会为了进入模式强制执行操作。

当前 Android 伴侣为 1.8.0（versionCode 11），沿用鲸鱼娘图标与 Liquid Glass 界面；API 31 起非低内存设备使用原生背景模糊，API 26 起及低内存设备使用半透明回退。手机独立 API、电脑离线聊天和草稿保留。手机请使用同签名新版 APK 覆盖安装；电脑源码更新后须从托盘退出旧进程并重启，只关闭聊天窗口不会加载新后端。安装和本版验收见 [Android 说明](../android/README.md)。

## 使用方式与会话

电脑端在输入框上方选择“电脑 Agent”；手机配对后选择“电脑 Agent”。同一对话会保留模式，发送后不会自动切回普通聊天。“继续”“修改刚才的文件”等后续消息使用相同会话的执行结果，不要求重复特殊措辞。手机“手机聊天”仍直接调用手机缓存或手动配置的 API，电脑离线时也可使用。

1.7.0 手机顶部仅保留单行电脑名称和实际连接状态，例如“我的电脑（在线）”或“我的电脑（离线）”；聊天标题留在历史列表。模式按钮和输入框下方不再显示说明或重复状态文字，任务进度和错误留在对应消息中。“查看电脑桌面”移到顶部更多菜单，不占用输入区。

手机通过已配对的加密通道调用 `agent.send`。桌面端用与本机相同的 ChatController、AgentService 和工具后端执行，回复、固定阶段进度、失败原因和对话记录同步回手机。`agent.cancel` 停止对应会话正在运行的任务。稳定请求标识和执行预留防止断线重发已经开始的操作；未知结果只查原操作，不自动执行一遍。电脑离线时不把 Agent 任务改为手机普通回复，也不把草稿排队等以后自动操作。

Agent 开始前不强制截屏；普通文件任务不依赖屏幕感知的开关、前台窗口或空闲时间。需要画面时，由已启用、已配置的 `computer_use` 工具实际观察并操作。手机顶部更多菜单中的“查看电脑桌面”仍是独立的只读截图功能，继续遵守屏幕感知的隐私设置，截图失败不阻断 Agent 的其它工具。

每个会话 UUID 有独立的原生工具记录，包括实际工具调用和结果，用于后续轮次继续任务；不同对话不会混用。生产环境将有界文本状态保存在现有用户配置目录旁的 `agent_checkpoints.sqlite3`，与聊天数据库和 Mem0 分开。完整退出再启动后，用户主动打开同一历史会话并发送“继续”才会执行新一轮；不会自动重放旧操作。恢复绑定会话首条消息 ID、工作区、权限、账户和模型；清空后新首消息会形成新的代际，即使检查点删除暂时失败也不能恢复已清空的状态。

原生回放保留最近 12 个完整轮次、最多 256 KB；历史图片字节、密钥和隐藏推理不进入检查点。SQLite schema 2 为超大单轮额外保存独立的待派发工具意图；旧 schema 1 以增量迁移保留数据。模型请求和顶层工具执行前必须先提交检查点并收到宿主确认，磁盘不可写时停止派发。中途中断后的未知结果会明确标记，不能自动再做一次。不会把手机导入的普通聊天文本伪装成实际工具结果。

## 实际工具范围

使用真实 `nanobot-ai==0.4.0` SDK，工具由 AURA 显式注册，使用电脑已保存的 API 和权限。一个 Agent 回合可以组合已启用的工具；GUI 模型仅在真正调用电脑操作时启动。

| 工具 | 当前范围 |
|---|---|
| `read_file` / `write_file` / `search_files` | 项目 `agent_workspace/` 或指定子目录内的 UTF-8 文本和文件名；不允许链接越界或任意外部路径 |
| `web_fetch` | 读取公开 HTTP(S) 地址的有界文本；不提供搜索引擎或登录 Cookie |
| `calculate` | 受限 AST 和 Decimal 精确算术，返回十进制字符串及是否精确；不执行 Python 或 shell |
| `analyze_csv` | 工作区 UTF-8 CSV 的分类小计、总额、记录数与源 SHA256；严格检查行、列、数字及混合币种，不静默跳过坏数据 |
| `verify_artifact` | 写入后独立读取文本、JSON、CSV 和 Office ZIP 容器；`csv_summary` 根据源 CSV 重算；每种检查明确声明验证范围 |
| `update_plan` | 替换完整任务清单，验证唯一非空步骤及最多一个执行中步骤；未完成步骤不能被悄悄删去 |
| `finish_task` | 检查未完成计划、未解决工具错误、产物校验及源版本；失败时不能直接标为完成 |
| `system_info` | 只读系统版本、架构、Python 版本、工作目录和可用磁盘空间 |
| `inspect_system` | Windows 实际内存与固定本地磁盘容量、已用和可用空间；不读取文件内容或执行命令 |
| `inspect_disk_usage` | 固定本地盘容量与已知目录分类的有界逻辑大小；6 秒扫描预算、条目上限、部分结果与未知值，不执行清理 |
| `inspect_directory` | 本地绝对目录的有界名称、类型和大小元数据；不读取文件内容，不跟随链接、云占位和重解析点，不访问网络或设备路径 |
| `discover_applications` | Windows 只读应用目录：真实 Desktop / Start Menu 快捷方式、桌面 EXE、已安装应用标签；返回最多 80 项当前候选 ID 与名称、描述，不返回绝对路径 |
| `open_application` | 在允许电脑操作时，使用当前发现结果中可启动的候选 ID 打开目标并验证可见进程窗口；不接受模型生成的路径、命令或参数 |
| `computer_use` | 在允许电脑操作且 GUI 模型配置有效时，通过 UI-TARS 实际截图、操作、再观察 |

三个 `inspect_*` 工具在 Windows 的任务工具权限下提供结构化只读观察，文件文本写入仍限于工作区。磁盘分类涵盖当前盘上的用户临时目录、系统临时目录、回收站、下载、Windows 更新下载及传递优化缓存等已知位置，不递归遍历整盘。超过 6 秒扫描预算、3 万条检查上限、目录访问受限或遇到不可读取条目时保留部分结果和原因；未测值不是 0。观察到的逻辑文件大小不是磁盘实际分配大小，也不承诺等量可回收空间。目录列表默认最多 80 项，名称和元数据只用于本次观察，不构成修改授权。工具不删除文件、不清空回收站、不调用清理程序；系统缓存应交给 Windows 存储设置处理。

应用目录查找需要“任务工具”或“电脑操作”任一权限，实际启动仍必须允许电脑操作。Agent 可根据名称的一部分、可执行文件名和描述查找，再通过本轮最新结果中的候选 ID 选择目标；已安装应用标签只能提供线索，不能直接执行。后续“好像叫 launcher.exe”可结合该会话先前的真实工具结果继续查找，并重新确认当前目录，不依赖固定句式或精确名称正则。多个不同目标仍有歧义时才提出澄清，不会随意选择第一个启动器。

现有本地 Steam / Epic `.url` 游戏快捷方式只在链接格式受支持且协议处理程序已注册时提供启动候选，模型不能自造协议 URL 或命令。看到关联启动器窗口不能证明游戏已打开；这种情况下保留“已发送请求但未验证游戏”的接手状态。每轮原生启动至多派发一次，派发前复核实际条目。只读查找无结果可以继续查看桌面；一旦启动已尝试、结果不确定或遇到 UAC，不会再换工具重试。

本次明确添加的图片可以随 Agent 任务发送。后续未添加图片的消息不会自动再附带旧图片；历史只保留图片文本占位。模型需支持图片输入，否则返回明确的图文接口错误。

Windows 文字输入使用固定的 `SendInput / KEYEVENTF_UNICODE` 辅助程序，输入正文经私有 stdin 传入，不读取或替换剪贴板。原组件的剪贴板失败和本机原键盘库的中文乱码已用实际窗口复现；修复后实测中文、emoji、换行和首尾空格，并通过真实模型完成测试窗口的输入、保存与磁盘内容核对。发送事件不完整时报告失败，不自动重发。图文接口拒绝图片时也不会静默删除图片后改成纯文字请求。

覆盖已有文件仍需本轮任务授权与显式 overwrite 参数。网页、历史、图像和工具输出是参考数据，不能自行增加操作授权。工具失败、取消或需要接手时不会伪报成功，也不自动重试已经派发的电脑动作。执行时长和步数默认均不设上限，可随时停止；单次模型请求和工具操作仍有独立超时。不会启用任意 shell、定时任务、插件自动发现或自发子 Agent；不会因选择模式更改电脑现有权限。

## 任务计划、计算与验收

普通问答仍可直接回答。处理多步任务时，模型可以维护计划，调用确定性工具计算，再写入和验收；新增工具沿用现有权限，不自动开启其他能力。计算工具不使用 `eval`、`exec`、子进程或模型代码。CSV 默认 UTF-8，可明确指定分隔符；不明确的金额格式、不同币种和非数值行会报错。

验收在最后一次写入后执行。格式可读与目标达成分别管理：文本读回只证明文件可读；JSON 检查拒绝重复键、NaN 和错误的标准汇总总额；CSV 汇总可绑定源、列、分组与源文件版本。显式的弱检查不能绕过最低格式校验或已知源核算，检查后目标或源变化必须重新举证。Office 当前仅验 ZIP 容器结构、必需 XML 与 CRC，不能据此声称内容、排版或真实 Office 打开已验证。任意 GUI 的最终画面也没有通用语义证明器，仍需按具体任务验收。

工具失败、材料缺失、计划未完成或验收失败会进入 `needs_user`，不是完成。模型可以在原任务授权范围内修正自己的输出并重新验收；不重新派发已经结束的 GUI 操作。同一规范操作和相同参数四次失败会停止无进展循环，成功步骤没有新增次数上限，不限步数和不限总时长不会移除单次操作的资源与超时边界。

执行过程沿用原有的可折叠记录，新增精确计算、核算表格、验收、计划和完成条件等固定标签，不展示模型隐藏推理、任意工具参数或密钥。没有新增模型角色、API Key 或单独设置窗口。

上游代码与许可证归属见 [DeepSeek Harness 参考说明](../third_party/deepseek_harness/README.md)。这里只移植计划验证算法并借鉴检查点顺序；独立计算和验收器是 AURA 实现，没有安装或执行上游插件框架。

## 设置和密钥

在“设置 → 任务助手”中配置：

1. 启用任务助手，按需允许任务工具、电脑操作。
2. 任务不设总时长和步数上限，可随时点击停止；工具任务沿用“模型与 API”中的聊天模型。
3. 如需电脑操作，另填 GUI 模型 Base URL、Model Name、动作格式与 GUI API Key，保存后启用电脑操作。

GUI 模型可以与聊天模型使用同一服务，仍独立保存配置和凭据。动作格式表示 UI-TARS 坐标/动作解析版本，不是 API 服务商品牌；目前支持 UI-TARS 1.5、UI-TARS 1.0、Doubao 1.5 的 15B/20B 格式。模型需要支持图像输入，并能遵守所选动作协议；名称中不含 UI-TARS 并不直接证明不兼容。

“模型类型”需与实际模型对应：专用 UI-TARS 使用原生坐标约定；其它通用视觉模型选择“通用视觉模型（像素坐标）”和 UI-TARS 1.5 动作格式。后者会对齐传入图片尺寸与动作解析坐标系，并明确 Windows 操作方式和本步截图尺寸。兼容适配不能让通用模型获得专用电脑操作模型的识别能力。

本机已验证并复用现有聊天 API 配置，GUI 密钥复制到独立凭据槽位，已开启任务工具和电脑操作。其它聊天、记忆、远程连接等设置保持原值；后续可在此页分别修改两个模型配置。

公开参数写入普通设置，GUI 密钥保存在 Windows 系统凭据管理器的独立槽位 `agent-gui-api-key`；不写入普通设置、源码、任务文件、进程参数或协议日志。后台需要的凭据仅通过 stdin 传入。界面中的密钥框只承接新输入，不回填已保存的密钥；留空保留原密钥，清除需要使用对应按钮。

聊天回复现在带有可展开的“执行过程”和“本次上下文”。执行过程记录真实公开阶段、用时、工具操作、电脑动作与模型原本给用户的公开分派说明；不读取或展示模型内部思维链。运行中可折叠，完成后默认收起，失败、取消和中断也能查看；记录随对应消息保存在本机，重开会话后继续可读。上下文面板展示实际发送的脱敏文本、模型名称、资料来源、历史消息数和明确标注的 Token 估算；图片用占位符，凭据与隐藏推理字段不保存。旧消息未记录的过程不会补造。

上下文默认跟随模型服务，不再采用应用的 8192 Token、16/40 条消息、Agent 64000 字符等人工窗口，也不因已有会话摘要游标删除历史原文。模型容量元数据明确可用时用于展示；未公开时显示由模型服务控制，不根据服务别名猜数字或用字节估算拒绝请求。实际超窗错误由服务端返回，应用不会静默删减后重试。任务规划与电脑操作也完整保留本任务资料、工具结果和图片/动作历史，不额外强制输出 Token 上限。公开状态和截图/动作“完成”在实际调用返回后记录，思考正文不作为操作记录。

安装状态只检查本地文件，不代表模型连接或真实桌面操作已经验收。nanobot Python 环境与 AURA 主环境分离；UI-TARS 使用 Node.js，SDK/operator 固定为 `1.2.3`。运行时不会自动执行 pip/npm 安装或更新。

## 电脑操作与停止

UI-TARS 保留 AURA 的现有界面，以后台截图、视觉动作和鼠标键盘操作完成任务。当前按官方本机 operator 的**单显示器**约束使用。模型配置由宿主提供；真实电脑任务的屏幕截图会发送给选定的 GUI 模型服务。

1.6.0 的 Windows 观察优先使用独立 Win32 原生采集。原生画面使用物理像素，提交模型前按实际鼠标输入的 DPI 坐标域归一化；图片尺寸、显示器和输入坐标须一致。截图前后确认显示器标识和范围，动作前再次检查当前显示器，避免屏幕切换后沿用旧坐标。这一处理不等于已完成多屏或混合 DPI 硬件验收。

一次观察最多尝试两轮采集。原生采集失败后，只有桌面可访问且目标为主显示器时才允许 SDK 截图回退，回退后仍检查尺寸、显示器和黑帧。锁屏/安全桌面和会话不可用立即停止；取消可终止等待。该回退只重新读取画面，不重放模型请求、鼠标键盘动作或整个任务。

| 安全错误码 | 含义与后续处理 |
| --- | --- |
| `gui_desktop_locked` | 已锁屏或处于安全桌面；在电脑解锁或处理系统提示 |
| `gui_desktop_session_unavailable` | Windows 桌面会话断开或不可访问；先恢复会话 |
| `gui_screenshot_display_unavailable` | 目标显示器不可用或发生切换；确认显示器后再发任务 |
| `gui_screenshot_black_frame` | 取得近乎全黑的无效画面；先恢复可见桌面 |
| `gui_screenshot_failed` | 无法进一步归类的采集失败；检查电脑当前桌面 |

无效画面不会作为成功观察继续点击。手机独立的“查看电脑桌面”仍走前台窗口的屏幕感知授权、暂停和隐私规则，不因新采集后端而读取受限画面。

Windows 管理员权限确认（UAC）需要用户在系统窗口中手动选择；助手不会绕过或自动确认权限。打开应用触发此窗口时应返回 `needs_user`，提示当前所需步骤，而不是等待到任务超时或宣称已打开应用。

聊天中的“停止”会取消本轮任务，传递到 nanobot 和 UI-TARS，并清理本任务拥有的进程。超时也会停止任务。取消在模型请求及动作边界生效：已经写入的文件、完成的点击或已发出的原生动作不会自动回滚；停止后的迟到结果不会冒充完成结果。

历史记录：1.7.0 的 GUI 子任务使用同一总任务的剩余时间，启动 Node 前和发送运行请求前重新核对，并扣除 10 秒供终止与结果整理；不会在规划后重新获得一整段 120 秒。剩余时间低于 GUI 最小预算时返回可缓存的 `timed_out`，不派发新的操作。当前版本默认使用 `timeout_seconds=0` / `timeoutMs=0`，表示不建立整项任务截止时间或 GUI 总时长计时器；120 秒与隐含的 600 秒任务上限均不再用于正常长任务。显式正数仅保留为开发兼容预算。截图、模型和已派发输入不会因超时或停止而自动重放。

本次实际故障的只读存档诊断：C 盘占用/可清理项检查于 2026-11-01 17:20 开始，先完成 `system_info`，随后进入 `computer_use`，在 9 次已完成 GUI 动作后于约 123 秒报总超时。旧 `system_info` 只包含工作区所在磁盘的可用空间，文件工具又限于工作区，缺少本地盘分类观察，因此该请求落入较慢的视觉导航。记录不能证明最后一次画面内容或具体点击效果；前一启动任务的公开元数据也不能证明游戏自身确实触发了 UAC。新只读工具补充实际观测能力，时间协调避免内外计时冲突，不等于已验收任意复杂电脑任务。诊断见 [runtime-diagnosis.json](../artifacts/companion-1.7.0/runtime-diagnosis.json)。

失败、超时和停止均不自动回放整项任务，也不切换模型重做。已启动过任务助手的消息有执行标记，不能通过重试旧消息重复执行；需要先查看实际结果，再发送新的任务说明。普通聊天回复与真正的工具完成状态分开判断，模型单纯说“完成了”不等于已经执行过工具；`needs_user` 表示需要用户接手。

2026-11-01 修复手机电脑协助中的重复工具调用：原流程在一次 GUI 调用返回后，规划模型若再次调用 `computer_use`，会触发 `GUI_ALREADY_USED`，将已有结果覆盖为失败。现在同一任务只派发一次完整原始目标，后续与并发工具调用复用首次结果，不重放操作；第一次失败、取消、超时或需要接手的状态仍保留。修复位于每次任务新启动的 nanobot worker 中，当前手机 APK 无需更新；旧失败任务不会自动重新执行。

同日另修复远程任务的截图前置条件：电脑前台为 AURA 自身窗口时，不再要求先取得该窗口截图才能接收明确电脑任务。该降级不提供图片，保留原始用户任务与现有分派核验；其它敏感窗口和授权规则继续阻止外发。主动远程读取仅跳过自动观察的有效空闲时长限制。此处涉及电脑主进程，需要退出并重新打开 AURA；现有手机 1.4.0 不用更新。

电脑操作失败会区分步数上限、模型请求、截图、原生输入和运行依赖，不再统一提示“检查配置”。会话只保存白名单中的静态 `agent_error_code`，不保存模型思考、截图、密钥或异常原文。已开始执行的任务不再显示可用的旧消息重试入口。

1.7.0 的远程同步内部 schema 6 刷新消息投影触发器，使新检查工具的“检查电脑状态”“检查磁盘占用”“查看目录信息”等白名单活动标签同步到已配对手机。1.8.0 的 schema 7 在此基础上增加有界的公开过程投影；聊天和设备授权继续保留，不需要删除数据库，也不发送工具参数或私有路径。

2026-11-01 起本机按用户要求取消固定步数限制，公开配置 `max_steps=0` 表示不限步数，同时用于 nanobot 和 UI-TARS。UI-TARS 在 SDK 内部使用真正的无限循环边界；nanobot 0.4.0 通过版本与源码结构核验的局部 runner 适配使用无界迭代器，不使用很大的整数充当“不限”。设置页只显示“不设上限”。当前也取消默认整项任务总时限：宿主、nanobot 与 UI-TARS 统一以 `0` 表示不限时，不使用极大常数替代。停止、用户接手、模型或单次工具错误仍可结束任务。GUI SDK 单次模型请求仍有独立网络超时，长任务每一轮重新计算这项请求时限，不累计为整项任务预算。旧配置的有限值可供开发兼容，普通设置页保存时统一取消时长限制；本机当前的 120 秒配置已按用户要求改为 `0`。旧失败消息的错误码仍保留，不能将历史失败提示当成新配置未生效。

本机目前的 GUI 配置别名为 `deepseek-flash`，`ui-tars-1.5` 表示动作解析格式，SDK/operator 不附带专用模型权重。仅凭服务端别名不能核实实际底层模型。当前路径没有调用 OpenAI Responses 的原生 `computer` 工具，也没有代码执行运行时、UIA 或 WPS COM；通用动作最终状态主要由模型 `finished()` 给出，尚无独立的 PPT 页数、保存结果或可打开性检查。

已对照 [OpenAI 公开 CUA 示例源码](https://github.com/openai/openai-cua-sample-app/blob/main/python-app/app/responses_loop.py) 和 [官方 Computer Use 指南](https://developers.openai.com/api/docs/guides/tools-computer-use)。公开示例通过 Responses API 及持久 Python/PyAutoGUI 环境执行模型生成的代码，用 `call_id` 和 `previous_response_id` 返回观察与衔接任务；官方也支持结构化电脑动作。公开仓库明确说明 OpenAI 产品使用自己的运行环境和额外控制，示例不代表 ChatGPT 完整内部实现。代码框架、模型能力与实际任务验收需要分别判断。

## 可折叠执行过程（1.8.0）

手机回复上方显示可展开的过程记录。运行时显示动态状态图标、耗时和实际阶段/工具步骤；任务结束后自动收起，点击可查看历史。仅同步固定公开标签、状态与时间，不同步模型隐藏推理、执行上下文、参数、文件内容或密钥；不新增总结模型请求。手机普通聊天也保存本机实际请求/完成阶段。保留单行在线状态、简洁输入区及停止入口。

电脑端从原请求消息的 `metadata.execution` 生成 `agent_trace`，只允许版本、状态、带时区的开始时间、用时和固定白名单事件。过程附在 Agent 用户请求消息上，完成后仍保留；助手回复的副本不重复投影。事件 ID 按真实数组序号生成，原始 ID 和任意详情不传给手机。移动投影最多保留最近 80 项有效事件，额外数量通过 `omitted_count` 明示；电脑完整归档不受该显示范围影响。

远程内部 schema 7 更新快照和增量日志的同一 SQL 投影，Android 缓存 schema 5 在升级后的下一次连接请求完整快照。离线记录在新快照完成前继续可读，配对、草稿和正常聊天不被清空。旧电脑缺少该字段或旧消息没有记录过程时，界面只显示实际已有状态，不补造步骤，也不显示原始隐藏推理。协议字段和安全边界见 [远程连接说明](REMOTE_CONNECTION.md#可折叠过程投影180)。
