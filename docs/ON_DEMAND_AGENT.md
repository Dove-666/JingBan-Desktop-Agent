# 桌面 Agent 与手机接入

电脑与手机的“电脑 Agent”直接进入 nanobot 原生工具循环，由模型选择工具、读取实际结果并继续任务；不依靠动作关键词或普通聊天分类器进入 Agent。普通文字回复仍可显示，但不等于电脑任务已完成；完成状态必须通过实际证据门。手机“手机聊天”使用手机 API，电脑离线时仍可对话；需要电脑工具的任务必须连接电脑。Android 安装版本和同签名覆盖安装说明以 [Android README](../android/README.md) 为准。电脑更新源码后须从托盘退出旧进程并重启。

## 使用方式与运行中交互

模式按会话保存，后续“继续”“修改刚才的文件”仍使用该会话的真实执行记录。手机标题显示当前对话主题，电脑连接状态以图标表示；模式按钮和输入框下不重复堆叠状态文字。运行过程、待回答问题、文件授权和交付文件位于消息区。

缺少必要选择时，`ask_user_question` 显示选项和自由回答；`request_file_access` 显示实际解析后的精确路径、文件/文件夹及只读/读写范围。只有用户明确答复才会继续授权步骤；等待、断线或模型文字不能代替批准。批准文件访问会扩展当前会话及安全范围内的该路径权限，不能扩展其它会话或整个磁盘。

执行中可发送“补充指令”，在下一次模型迭代接入同一任务；待确认问题优先使用卡片答复。手机通过 `agent.answer` / `agent.steer` 发送即时请求，严格核对会话、当前任务、问题 ID 和已配对电脑身份，不进入待发队列，不在重连后自动重放。过期、已答复或旧任务的问题不能批准新请求。协议见 [远程连接](REMOTE_CONNECTION.md)。

## 实际工具范围

当前 [tool_catalog.py](../agent_backend/nanobot/tool_catalog.py) 定义 **41 项**受控工具及参数 schema、权限、平台和副作用类型；worker 注册、宿主能力列表、检查点及公开活动使用同一目录。41 是目录总数，实际可用集合取决于权限、操作系统、浏览器和 GUI 配置；受限项目计算在本机仍关闭。安装状态和 `readiness` 表示配置/组件检查，不代表真实任务已完成。

| 工具组 | 工具 | 条件与范围 |
| --- | --- | --- |
| 文本文件 | `read_file`、`write_file`、`edit_file`、`search_files` | 任务工具权限；默认工作区，外部文件须经宿主明确授权 |
| 文档与产物 | `read_document`、`create_document`、`describe_artifact`、`verify_artifact`、`render_document`、`inspect_document_page` | 任务工具权限；格式库与相应渲染组件须可用。本机已配置独立 LibreOffice，页面核对另需支持图片的模型和当前 PDF 版本 |
| 确定性计算 | `calculate`、`analyze_csv`、`run_code` | 任务工具权限；受限 AST/Decimal、真实 CSV 核算及无文件/网络接口的 QuickJS JSON 计算 |
| 只读资料子任务 | `delegate_research` | 当前已授权 UTF-8 文件、独立子任务与实际来源版本；不扩大权限 |
| 受限项目产物 | `compute_project_artifact` | 仅宿主明确启用后注册；本机因隔离缺口保持关闭，不提供通用 Python、终端或项目构建 |
| 计划与完成 | `update_plan`、`finish_task` | 任务工具或电脑操作至少一项权限 |
| 记录与交互 | `recall_context`、`ask_user_question`、`request_file_access` | 同上；宿主验证来源、会话和真实答复 |
| 网页来源 | `web_search`、`web_fetch` | 任务工具权限；公开搜索与有来源、可分页的 HTTP(S) 文本 |
| 匿名网页操作 | `browser_navigate`、`browser_observe`、`browser_act`、`browser_tabs`、`browser_switch` | 任务工具权限及已安装的受支持 Edge/Chrome；独立匿名浏览器 |
| 历史图片 | `inspect_image` | 任务工具权限、当前会话允许的附件 ID 和支持图片的模型 |
| 系统观察 | `system_info`、`inspect_system`、`inspect_disk_usage`、`inspect_directory` | 任务工具权限；后三项限 Windows，仅有界只读观察 |
| 应用发现与启动 | `discover_applications`、`open_application` | Windows；发现需任一权限，实际启动需电脑操作权限和当前发现候选 |
| Windows 控件 | `desktop_windows`、`desktop_activate`、`desktop_observe`、`desktop_act`、`desktop_verify_state` | Windows 电脑操作权限；实际窗口/控件引用和动作后读回 |
| 视觉电脑操作与验收 | `computer_use`、`verify_desktop_goal` | 电脑操作权限及有效的全局模型配置；模型须支持看图与动作输出，运行时还依赖桌面会话和 UI-TARS 组件 |

同一任务可组合已确认的应用启动、UIA 控件操作和视觉步骤，不再整轮互斥。桌面操作按实际动作串行、使用新观察和当前引用；确认完成后可以处理下一项具体子任务。派发后的结果不明会阻止重复该副作用，不能换工具把同一次点击、提交或启动再做一遍。模型提出的子任务仍受原用户目标及用户补充指令约束。

没有注册任意 shell、删除工具、Cron、插件自动发现或自发子 Agent。网页、图片、历史和工具输出都是参考数据，不能增加权限。系统目录观察也不授予读取正文、清理缓存或删除文件的权限。

## 文件、文档与交付

`read_file` 返回哈希、总长度、截断标记和 `next_offset`；必须继续读取所需范围，不能把第一页当完整材料。`search_files` 提供分页及命中上下文。外部路径通过 `request_file_access` 向宿主申请，读授权不会变成写授权，链接解析后越界仍拒绝。授权与文件工具、CSV 分析、文档工具和验收器共享，模型不能自行修改授权列表。

新建文件默认不覆盖。替换文件需 `overwrite=true` 及先前观察到的版本或明确 `expected_hash`；写入使用原子替换，版本变化会拒绝。`edit_file(path, old_text, new_text, expected_hash=...)` 适合小修改，未命中或多处匹配默认拒绝。用户明确需要的空文件可以合法验收，不再一律当成失败产物。

`read_document` 支持 PDF、DOCX、XLSX、PPTX，返回来源、版本和分页信息。PDF 可用 `pages="1-3,5"`；XLSX 的 `section` 为工作表名，PPTX 为从 1 开始的幻灯片序号；`expected_hash` 防止跨页读到不同版本。格式或参数不适用时明确报错。

`create_document` 使用结构化 `spec`，不是模型自行执行脚本：

```json
{"path":"report.docx","kind":"docx","spec":{"title":"工作记录","sections":[{"heading":"结果","paragraphs":["已核对的内容。"]}]}}
```

DOCX/PPTX 的 `sections` 可含 `heading`、`paragraphs` 和 `table:{headers,rows}`；XLSX 使用 `sheets:[{name,columns,rows}]`。生成后检查真实包结构并读回内容，表格字符串按文本保存。格式及内容读回通过，不等于页面排版或全部用户要求已验收。

`render_document` 尝试由隔离、明确归宿主所有的 Microsoft Office 实例导出 PDF，随后检查 PDF 及内容证据；不附着用户已打开的 Office/WPS，不代点修复、许可、登录或 UAC。源版本会复核；输出仍需写授权，`expected_hash` 保护的是被替换的目标 PDF。**本机本轮原生渲染未通过**：Word 出现修复提示，PowerPoint 需要启动交互，Excel 未取得可绑定的安全模式文档对象；没有成功的原生 PDF 导出或预览页。详见 [Office 实机记录](../artifacts/agent-upgrade-20261102/office/summary.txt)。工具存在不能作为 Office 当前可用的证明。

已验收文件由宿主复制为会话绑定的不可变交付副本。消息区文件卡片提供另存为；手机点击后才分块下载，核对元数据、长度和 SHA256，再由系统保存对话框选择位置。`verification_scope` 表明实际验收范围；本地目录字符串不等于手机已取得文件。`artifact.list/get` 只接受会话与不透明引用，不接受任意电脑路径。

## 上下文、历史图片与检查点

原生工具记录按会话 UUID、首消息代际、模型/账户及权限范围隔离。生产状态包括 `agent_checkpoints.sqlite3`、事实/观察归档和执行事件记录，与聊天数据库及 Mem0 分开。检查点数据库当前 schema 2；远程同步内部 schema 8 是另一套版本号。

热回放仍控制在最近 12 个完整轮次和约 256 KB；这不是直接丢弃更早事实。旧工具结果、长正文和更早记录进入有范围隔离的 ObservationStore，当前请求保留事实摘录、来源引用及进行中的调用配对，通过 `recall_context` 按引用恢复原文。活动任务还维护工作集；已知模型容量与实际用量可用于预算，明确超窗时只收缩可恢复的资料投影并有限重试模型请求，不重做工具副作用，也不删除图片掩盖接口错误。摘录和估算不等于无限上下文或完整事实已全部放进一次请求。

本次显式图片只作为本次附件发送。用户追问旧图时，Agent 可以从宿主给出的当前会话图片目录选择 `inspect_image`；实际像素经私有资源请求按需取得，不会把旧图又附成一条新的用户图片消息。其它会话、已删除或不可用图片拒绝访问，模型必须支持图像输入。

模型请求和顶层工具执行前须完成持久检查点并收到宿主 ACK；失败时停止派发。退出后用户主动打开同一会话并发送新消息才会继续，没有后台自动恢复操作。清空或删除会话撤销对应归档；普通手机导入的文本不能伪装成已执行的工具结果或授权。

## 网页与浏览器

`web_search` 查找公开标题、链接和摘要；`web_fetch` 再取正文、来源哈希、链接和分页。网页内容不可信。公开文本读取保持 2 MiB 原始来源上限，任务内完整快照 LRU 最多 8 份；更早正文从观察归档分页，URL/来源元数据放任务私有临时索引，不重新 HTTP 获取后假装仍是旧快照。无归档的兼容调用读取已淘汰来源会返回 `WEB_SOURCE_EVICTED`。

DOM 工具只控制鲸伴自己的匿名 Edge/Chrome 会话、标签和新观察到的元素引用，不读取用户浏览器配置、Cookie、登录态或其它窗口。陈旧/已消费的引用不能直接重放；网络提交结果不明时先观察核实。浏览器缺失会明确标为不可用，不会运行中安装浏览器。真实站点登录、验证码、账号任务和跨网可达性不因此获得保证。

## 任务计划、计算与验收

计划可随证据重排；优先保留稳定步骤 ID，取消或替代路线需注明原因，不能把未做的步骤写成完成。探索性查找失败可以由之后的真实证据替代；缺少必需材料、真实产物验收失败和未知副作用仍阻止完成。`finish_task` 检查活动步骤、必要来源、最后写入后的产物及未解决效果，不以模型说“完成”代替证明。CSV 汇总契约可选，但一旦绑定真实来源、列和版本，就不能用弱文本检查绕过重算。

worker 为实际 Agent 任务启用 `TaskHarness(require_evidence=True)`。仅有计划、`finish_task` 或纯文字回复不能把任务标为 `completed`，会保留回复正文并返回现有的 `needs_user`；实际工具证据还须通过相应目标/产物验收。手机普通直连 API 聊天不受这道工具证据门影响。这是任务完成语义，不是关键词切换模式，也没有新增 `answered` 状态。

独立桌面验收现在可联合新截图与真实 UIA 前后状态。只有 `DesktopControls.observe` 的实际观察能写入 GuiBridge 内部记录，最多 8 个状态、64 KiB，剔除密码、私有引用和密钥。相邻同状态即使 snapshot UUID 不同也合并，保留首末真实捕获序号、时间与省略数；捕获序号不是视频/文档等业务对象的序号。这些内部状态不进入手机公开过程。没有 UIA 证据的路径仍按原严格条件验收，不放宽目标身份、先后时序或高信心要求。

## 电脑操作与停止

默认 `max_steps=0`、`timeout_seconds=0`，不设整项任务步数或总时长限制；网络、截图、单次工具和资源大小仍有界。连续无进展失败会停止。用户可随时停止，取消传递到 SDK 和本任务拥有的子进程；已经完成的写入、点击或提交不自动回滚，结果不明不自动重放，迟到回复不会冒充完成结果。锁屏、安全桌面、不可访问会话和 UAC 需要用户在电脑处理，不会绕过。

## 可折叠执行过程（1.8.0）

执行过程显示真实公开阶段、动态状态、用时和工具步骤，完成后自动收起，可再展开。模型隐藏推理、任意工具参数、凭据和图片字节不作为公开过程同步。手机标题仍是会话主题，连接状态使用紧凑图标。

## 设置和密钥

在「模型与 API」中配置一次，普通聊天、任务工具和电脑操作共用相同的 API 地址、模型名称与密钥。电脑 Agent 页面只保留权限开关，不再创建独立模型、密钥和运行诊断表单。电脑操作统一使用 UI-TARS 1.5 的通用视觉像素坐标适配；旧的独立模型配置不作为请求目标。模型本身仍须支持图像理解与动作输出，复用配置不会自动补齐模型能力。主 API 密钥保存在系统凭据库，后台仅经 stdin 接收；运行时不自动 pip/npm 安装。UI-TARS SDK/operator 固定为 1.2.3，nanobot SDK 为 0.4.0；型号别名不能证明底层模型能力。

## 当前验证边界

补齐跨模态证据前，三次独立 QA 尝试虽各保存一次且内容正确，仍因时序证据不足而超时，不能记为验收通过。修复后的首轮真实配置模型在自有、不透明、前台的单显示器 QA 窗口中完成 8 次工具执行，耗时约 33.781 秒：保存回调一次，控件文字/标签与磁盘字节相符，独立父目标验收为 `verified`，`finish_task` 被接受。见 [实机跨模态验收](../artifacts/agent-upgrade-20261102/real-gui-structured-verified.txt)。这只证明该受控任务，不承诺任意跨应用、游戏或 Office 任务成功率。

另有真实 Host→隔离 SDK→localhost 模型的问答、授权、纠正、历史图片和 DOCX 交付回归，以及桌面/Android 界面和协议检查，见 [跨层验收](../artifacts/agent-upgrade-20261102/runtime-controls/handoff.txt)、[UI 验收](../artifacts/agent-upgrade-20261102/ui/handoff.txt)。合成模型和模拟器证明所测控制链路，不证明真实手机流量到家庭宽带可达；本轮跨网与公共中继实际转发仍未实测。Office 原生渲染失败边界见上文。
