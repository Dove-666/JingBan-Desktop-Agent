# 桌宠体验问题修复 · 2026-10-31

本轮处理体验复查中的六组问题，保留白色聊天界面、当前角色素材、已有会话和用户配置。旧审阅报告保留作为复现记录；本文说明修复后的行为。

## 修复内容

| 问题 | 修复后的行为 |
| --- | --- |
| 聊天失败后无法恢复 | 每条用户消息持久保存等待、失败、取消或中断状态。切换会话或重启后仍可在原消息旁重试；重试携带明确的会话和消息 ID，不重复保存用户问题。未配置 API、历史加载失败与回复失败分别提供设置、重新读取和重试入口。 |
| 等待时不能停止 | 增加“停止生成”，取消正在等待的 HTTP 请求。迟到回复不会追加到错误的会话或覆盖新请求；数据库提交已开始时不会谎称取消成功。恢复旧 pending 状态使用数据库条件更新，避免将已经完成的消息改成中断。 |
| 页面故障后无法继续聊天 | 页面故障提供“使用兼容聊天”和重新加载。原生聊天沿用现有会话及每会话草稿；返回白色新版界面后仍保留草稿。缺少 WebEngine 模块也会显示恢复入口。 |
| 用户改口后同时使用新旧偏好 | 新增“编辑 / 纠正记忆”和“更正历史”。使用真实 Mem0 `update/history` 更新原记录并保留审计历史；验证所属用户和原值，防止覆盖刚被修改的事实。明确且有原话证据的改口可自动更新同一条事实；有歧义时提示人工纠正，不靠相似度擅自删除记忆。注入上下文时排除已失效事实，并附可用的更新时间。 |
| 记忆超过 1000 条后找不到 | 管理操作遍历当前用户全部 namespace，按完整文本筛选后分页，每页 100 条。显示真实总量、匹配量和当前加载范围；其他用户的数据不进入列表，也不会被编辑或清除。 |
| 自动记住了但列表不刷新 | 自动提炼成功通知记忆控制器刷新，保留搜索词、分页和选择；忙时合并刷新请求。列表、搜索、删除和历史查看无需模型在线。编辑文字需要当前记忆使用的 Embedding 可用。 |
| 缩小角色后气泡字太小 | “调试面板 → 角色控制 → 评论气泡阅读”提供独立的 12–22 pt 字号，默认 14 pt，实时保存。50% 角色不再将字号一起缩小。关联聊天的长气泡支持悬停暂停、上一页、下一页和滚轮翻页，点击正文进入相应消息。 |
| 自定义角色被表情替换 | 自定义图片保持自身角色身份；没有配套表情素材时使用逻辑状态和轻量反馈，不切换成项目默认鲸鱼娘。默认角色继续使用已有表情及动画素材。 |
| 动画人物拖不到边缘 | 拖动时冻结当前帧，按实际非透明轮廓限制位置。松手后短暂平滑恢复到能够容纳后续动画的位置，避免立即弹回或裁切；恢复途中到达的表情请求不会突然换图。 |
| 日常操作不完整 | 回复中的 HTTP/HTTPS 链接可打开和复制，地址由原生层校验；历史侧栏显示更新时间和概况。窄窗口历史抽屉限制键盘焦点，Esc 返回触发按钮。清除 API Key 增加确认，取消时保留已保存密钥与输入草稿。 |
| 看不懂感知为何安静 | 聊天页与感知页显示运行状态，提供本次运行暂停；感知页显示观察、分析与发言冷却倒计时、本小时剩余次数、最后成功分析时间及预览采集时间。保存失败不消耗发言次数或事件去重；仅存档而未显示的评论不消耗自动发言次数。 |

## 数据与兼容

- 不重建用户的 SQLite 或 Mem0 数据库。请求状态继续保存在消息 metadata，恢复过程使用事务中的条件更新。
- 气泡字号使用新增的 `pet/reading_font_points` 设置；缺少或损坏时回退到 14 pt。既有角色大小设置继续独立生效。
- Mem0 仍使用现有开源 SDK 和本地 Qdrant；没有新增另一套记忆库。手工纠正保留原 ID 和 SDK 历史。
- 本次运行暂停不改写保存的记忆/感知授权。删除会话与删除长期记忆继续独立。
- 未修改或生成角色素材，未恢复工作区原先删除的文件，未提交或推送仓库。

## 安装与启动

依赖未新增。已有环境直接启动：

```powershell
.\.venv\Scripts\python.exe main.py
```

需要安装依赖时：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install -r requirements-memory-local.txt
```

修改前端源码后，在 `frontend/chat-ui` 执行 `npm.cmd run build`。日常启动直接读取随项目打包的本地页面，不需要运行开发服务器。

新入口与操作步骤见 [日常使用](DAILY_USE.md)。运行中的旧进程需要退出桌宠后重新启动才能完整加载 Python 修复；本轮测试没有强制结束生产进程或替用户切换会话。
