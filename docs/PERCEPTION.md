# 屏幕、摄像头感知与主动交互

## 摄像头识别

在「调试面板 → 摄像头」使用「开启摄像头」开关，选择设备并查看本地实时预览。托盘提供独立开关，聊天工具菜单的「摄像头设置」可直接打开此页。默认关闭；开关只开启本地采集，只有单独允许「发送摄像头画面给已配置 API」后才进行远程识别。「评论当前画面」使用当前显示的预览；定时识别复用屏幕识别的画面变化检测、请求间隔与评论规则。

摄像头与屏幕有独立权限、设备状态、取消令牌和事件；两者共用主动发言预算，避免重复打扰。评论保存到当前会话并标明「来自摄像头」，后续聊天和导出保留来源。摄像头帧仅在内存中保留低分辨率预览，不录制视频、不接入麦克风；关闭或暂停会释放设备并清除预览，断开或权限错误会自动关闭。相机观察不会被当作用户自述写入长期记忆。

运行 `python -m unittest tests.test_camera_observer tests.test_camera_controller tests.test_camera_ui tests.test_camera_conversations tests.test_camera_web_ui` 可验证合成画面、独立权限、取消与设备释放、SQLite 迁移、导出和界面。开发验证使用合成帧和 localhost 模型接口；真实设备权限、取景与画质需在本机打开开关后确认。

## 屏幕感知

AURA 复用现有 PySide6 桌宠、统一角色控制器、OpenAI 兼容 API、系统凭据和调试面板，提供可选的前台窗口观察与主动互动。R7 已增加独立聊天会话、屏幕评论关联与可选 Mem0 长期记忆，见 [会话与记忆说明](SESSIONS_MEMORY.md)。没有引入 Live2D、OCR、电脑操作或执行模型指令；原始鲸鱼娘 PNG 保持不变。

事件后的追问使用当前会话文字情境及少量相关记忆，不发送所有历史或保存屏幕截图。聊天默认 8192 Token；Mem0 提炼使用独立预算，默认总量 65536、输出预留 1024，超额拒绝提炼模型请求，但 SDK 在此前可能已调用 Embedding 检索。记忆管理列表当前最多读取 1000 条，聊天最多注入 3 条相关记忆。

当前修订为 `2026.10.30-r7`：标题栏显示修订号，调试面板右上角显示“会话与记忆版 R7”。沿用原有屏幕识别、陪伴评论和手动评论规则；新增的正式评论先保存到明确会话，再以可点击气泡显示，打开后能围绕关联文字摘要追问。箭头继续指向角色，字号至少 14 号，长评论换行并自适应高度。

前轮本机验证汇总：[R2 修复报告](../artifacts/r2_preview_fix_report.json)（`artifacts/` 不提交 Git）。R2 记录用于说明既有采集与预览修复，R3 评论功能的执行结果以本轮最终验证记录为准。

## 安装和启动

Windows PowerShell，在仓库目录执行：

```powershell
# 已有 .venv 时跳过创建环境
py -3.10 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py --debug-panel
```

也可双击 `start_pet.bat`，再右键角色打开调试面板；`start_pet.bat --debug-panel` 可直接显示面板。屏幕观察没有增加新的截图依赖，沿用 PySide6 6.12.0、OpenAI SDK 2.54.0、keyring 25.7.0。需要可选 Mem0 长期记忆时另行安装 `requirements-memory.txt`，详见 [记忆安装](SESSIONS_MEMORY.md#安装与启动)。

单击角色会保留原有开心/惊讶动作，并打开独立聊天窗口。拖动超过系统阈值后，松开不触发单击。关闭调试面板或聊天窗口不退出桌宠。

## 启用方式

屏幕感知和远程发送首次运行均默认关闭；未启用时不会自动读取前台信息、截图或发起屏幕分析请求。已保存的用户选择会在重启后恢复。

1. 在“API 设置”中填写服务商的 Base URL、Key 和支持图片输入的模型名称，保存并测试。文本连接测试成功仅验证聊天接口，不能代替图片输入能力验证。
2. 打开第四个选项卡“屏幕感知”，勾选“启用本地前台窗口观察”，按需要调整参数，点击“保存参数”。此时可以只做本地观察。
3. 点击“3 秒后本地观察”，在倒计时结束前切换到需要观察的应用。采集完成后返回面板查看预览和变化详情；此按钮始终不调用 API，即使已经允许远程分析。倒计时不会自动移动、隐藏或切换窗口。R2 在手动预约期间跳过自动轮询，避免自动请求占用观察；完成或取消后恢复原有轮询，不改已保存开关和请求冷却。
4. 需要完整主动互动时，单独勾选“允许向已配置 API 发送低分辨率前台画面和窗口标题”。确认发送提示后点击“保存参数”，远程权限才生效。
5. 定时观察时也需要让目标普通应用位于前台。AURA 自身窗口会被跳过；返回调试面板会保留最近一次安全预览，并明确标为“上次本地预览”，不会把面板自身截图为新观察。敏感、排除或无法确认的其他窗口仍会清空预览。
6. “互动风格”默认“陪伴评论”，可回应清晰、适合互动的普通视频等内容；选择“只在重要时说话”可恢复重要事件优先的风格。修改后点击“保存参数”。两种模式均保留自动发言冷却、每小时限额和去重。
7. 需要立即检查评论时，先取得安全预览并返回 AURA，再点击“评论当前画面”。它只发送当前缓存的安全预览，不再截图；仍需要本地观察和远程发送均已启用并保存，并使用已有 API 配置。按钮不会自动开启权限。请先检查预览是否是你希望评论的内容。
8. 取消本地观察、保存新参数或确认“清空本次事件”会取消尚未执行的手动倒计时；关闭面板不会清除会话状态，也不会取消已经安排的本地观察。取消本地观察或远程发送并保存，会取消当前分析并忽略晚到结果。退出桌宠会停止整个观察和请求流程。

远程分析会将符合本地规则的前台窗口预览、进程名及窗口标题发送给 API 设置中的服务商，可能产生该服务商的费用。截图与标题是实际发送内容；隐私规则不能保证识别所有敏感信息，应按使用场景补充关键词和排除进程。

## 默认参数

| 参数 | 默认值 | 调试范围或行为 |
| --- | --- | --- |
| 启用本地观察 | 关闭 | 独立开关，保存后生效 |
| 允许远程分析 | 关闭 | 独立开关，首次勾选需确认发送 |
| 互动风格 | 陪伴评论 `companion` | 可选只在重要时说话 `quiet`；保存后生效 |
| 本地观察间隔 | 10 秒 | 5～30 秒 |
| 模型请求最短间隔 | 60 秒 | 30～600 秒；请求失败也计入间隔 |
| 画面变化阈值 | 0.08 | 0.01～1.00 |
| 主动发言冷却 | 180 秒 | 30～1800 秒 |
| 每小时主动发言上限 | 6 次 | 1～30 次 |
| 用户无输入暂停阈值 | 600 秒 | 60～7200 秒 |
| 截图最长边 | 640 像素 | 保持原比例，只在内存处理 |
| 模型图片输入 | JPEG，质量 70 | 单张低清图片，不发送完整桌面 |
| 本地变化采样 | RGB 64×36 | 平均绝对像素差，结合前台应用/窗口变化 |
| 去重缓存 | 最多 256 项，600 秒过期 | 保存画面指纹及事件摘要键，LRU 淘汰 |
| 调试事件 | 最近 30 条 | 只保留在本次进程内存中 |

参数通过已有 `SettingsManager` 写入当前用户的非敏感 INI。API Key 仍保存在 Windows Credential Manager，不写入 INI。清空本次事件会清掉预览、详情和去重记录，保留当前请求间隔及发言配额，避免通过反复清空绕过限制。

## 工作流程与职责

```text
QTimer 定时观察
  → 读取前台进程、标题、无输入时长
  → 本地隐私/应用/空闲过滤
  → 只采集目标窗口与一个显示器相交的可见区域，遮蔽其他窗口遮挡并缩小预览
  → 再次核对前台窗口，情境变化则丢弃
  → 未遮挡区域近全黑或采集不可用则本地跳过，不调用模型
  → 本地画面变化检测
  → 远程权限、聊天占用、最短请求间隔、画面去重检查
  → Qt 工作任务调用已有多模态 API 传输
  → 校验结构化情境，再次确认当前窗口仍安全且一致
  → 事件去重及主动行为决策
  → 安静 / 只动作，或把正式评论和文字事件事务写入明确会话
  → 保存成功后通过统一角色接口显示关联气泡，点击可进入该会话
```

| 模块 | 职责 |
| --- | --- |
| `ScreenObserver` | Windows 前台进程/标题与最后输入时长；在截图前过滤，再采集目标窗口区域并复核情境。元信息、权限或截图失败时安全跳过，不回退到整桌面截图。 |
| `windows_capture.py` | 以物理像素裁剪目标窗口与显示器的交集，复制该可见区域；遮蔽采集前后其他窗口的遮挡范围，处理 DPI 和释放 GDI 资源。 |
| `capture_quality.py` | 只检查未遮挡像素，检测近全黑或无有效画面；不依赖模型判断截图是否可用。 |
| `ChangeDetector` | 缩小画面后计算差异和指纹，识别应用/窗口与尺寸变化；与接受的基线比较，可累计较慢的变化。 |
| `ContextAnalyzer` | 将单张低分辨率图及有限元数据交给已有 `ApiClient.request_text`；按互动风格或明确评论请求调整提示，只解析、校验情境数据。 |
| `EventDeduplicator` | 有界、带过期时间的画面/事件去重，避免相同画面重复请求与相同事件重复反馈。 |
| `ProactiveAgent` | 根据互动风格、置信度、重要性、用户操作、发言冷却和每小时配额决定 quiet、motion 或 speak。 |
| `PerceptionSettings` | 参数默认值、范围校验、隐私关键词和排除应用偏好。 |
| `PerceptionController` | 定时器、异步工作任务、取消、会话事件、界面信号与现有角色/聊天模块之间的编排。 |
| `PerceptionPanel` | 独立调试面板第四选项卡；显示参数、过滤后的详情、内存预览、状态和最近事件。 |

屏幕读取使用 Windows API 和 Qt 已有能力，无键盘内容采集、输入钩子或持续视频录制。图像编码、HTTP 请求和模型结果解析放在 Qt 工作任务中；同一时间只进行一项屏幕分析，重叠观察跳过。R7 继续复用聊天控制器，将被决策选为发言的评论和必要文字摘要关联到发起分析时的明确会话；该会话追问可有限量使用相关摘要，其他会话不自动继承它。成功归档后若新的用户操作优先而抑制气泡，正式消息仍留在历史。

## 情境输出与主动行为

分析提示尝试获得以下 JSON，不强制服务商专有的 JSON 输出模式：

```json
{
  "kind": "interesting",
  "summary": "前台出现一张有趣的图表",
  "reply": "这个图表挺有意思呀！",
  "emotion": "happy",
  "importance": 0.8,
  "confidence": 0.9,
  "event_key": "new-chart"
}
```

`kind` 白名单为 `none`、`achievement`、`error`、`interesting`、`work`、`media`、`other`；`emotion` 继续沿用 `neutral`、`happy`、`surprised`、`sleepy`、`angry`、`thinking`、`talking`。分数必须为 0～1 的有限数值。格式错误、普通文本、未知状态或不可信结构会降级为安静，不把模型输出执行为 Python、命令或电脑操作。

R2 提示要求普通内容保持安静，模型常将普通视频分类为 `none`；策略会首先将 `none` 判为 `quiet/no_actionable_event`，其余事件还需达到 0.65 重要度。这就是截图里“已经分析到视频，但鲸鱼娘没有评论”的原因，单独降低重要度阈值不能解决 `none` 和空回复。

R3 的自动反馈按两种风格处理：

- **陪伴评论 `companion`（默认）**：提示模型为清晰且适合互动的普通媒体内容给出 `media` 或 `interesting` 分类及具体、自然的候选评论；这两类在重要度至少 0.10、置信度至少 0.60 且回复非空时可以自动发言，普通内容不需要被虚构成重大事件。其他类别仍使用 0.65 重要度门槛。
- **只在重要时说话 `quiet`**：普通内容保持安静，保留重要度至少 0.65、置信度至少 0.60 且有回复的自动发言要求。

两种风格下，`none`、无有效画面或低置信度都不会说话；不符合发言重要度或缺少回复的有效事件可以只播放动作。自动发言仍受默认 180 秒冷却、每小时最多 6 次及画面/事件去重限制，达到限制时可降级为静默动作。用户聊天、聊天后短暂时间、长时间无输入及拖动期间优先保持安静。自动分析返回时窗口已经切换、命中隐私规则或权限已关闭，也不会显示旧情境反馈。

事件区域会显示“分类”和模型提供的“候选评论”，以及动作、中文原因和原始原因码，例如“主动发言冷却中（cooldown）”。候选评论不代表已经说出；只有“发表评论（speak）”的事件会在“鲸鱼娘”项保留实际回复。

### 手动评论安全预览

“评论当前画面”是用户明确发起的一次远程请求，使用最近一次通过隐私过滤、仍保存在内存中的预览及有限元数据，不截取 AURA 面板或新的桌面内容。AURA 在前台时可以查看并评论旧预览；它不是对实时画面的持续观察。

此请求可覆盖 `quiet` 模式对普通内容保持安静的要求，绕过自动重要度门槛、事件去重、主动发言冷却和小时配额，不消耗或重置自动发言计数。它仍要求有效的非敏感可见内容、可信度达标和真实候选回复；API 错误、无效结果、`none` 或空回复不会变成预设的伪评论。模型只看到一张预览，不应猜测人物身份、声音、遮罩内容或前后发生的事情。

本地观察和远程发送均需已经启用；请求占用、聊天或拖动时不能重复请求或抢占反馈。请求前及返回时都会检查情境：可停留在原来源窗口或 AURA，切换到其他窗口、隐私/排除/未知情境，或关闭权限、清空预览时，会拒绝或丢弃结果。该明确请求不会削弱自动观察对 AURA 自身窗口的跳过规则。

动作和语言都通过 `PetController` 统一接口触发，不由 API 模块直接改绘图。`play_motion` 在缺少素材时仍提供轻量跳动，不显示表情语气泡。评论气泡使用至少 14 号字体，按全文测量、换行和增高，长评论延长阅读时间，不足时分页，跟随角色并限制在屏幕工作区。R7 的关联屏幕评论气泡可点击进入对应会话，不抢键盘焦点；普通动作反馈仍鼠标穿透。正式评论和文字摘要保存在 SQLite，调试列表及图像预览仍为内存数据。缺少表情 PNG 时沿用原图，没有实现真实面部变化、嘴型或新增图片。

## 隐私与数据边界

- 默认屏蔽常见密码管理器进程，以及标题包含密码、验证码、登录、银行、支付、私密等中英文关键词的窗口；调试面板可编辑列表。
- 排除、敏感、长时间无输入或无法确认的窗口不截图；详情只显示过滤原因，清空旧预览，不显示被过滤的标题。AURA 自身窗口是单独的调试例外：不截图、不分析自身，只保留并标记上次已通过过滤的预览，方便返回面板检查。
- 截图和逐次观察详情只在内存，默认不落盘。R7 会将被决策选为发言的评论及必要应用名、时间、事件 ID、类型和短文字摘要保存到独立会话 SQLite，普通聊天也持久保存。安静/只动作的观察和未被决策选为发言的候选不全量归档。Mem0 另行启用，只提炼明确的耐久用户事实，不把每次屏幕观察和完整聊天写成长期记忆。
- 同时检查截图前后与回复到达时的前台情境，避免应用切换后继续展示旧结果。自动分析切回 AURA 时不触发旧反馈；明确点击手动评论安全预览时允许在 AURA 内等待结果，其他隐私和情境校验继续保留。请求已经发送的内容无法从服务商端撤回；取消后本地会忽略晚到结果。
- 禁用 SDK/HTTP 敏感调试日志，错误界面不转发未经处理的服务商响应或原始异常。当前 API Key 会在相关文本中脱敏。
- 本地标题/进程过滤是启发式规则，没有 OCR，也不保证识别图片中的账号、聊天、财务、医疗或其他敏感内容。普通窗口内的敏感内容仍可能通过过滤。
- 仅复制目标窗口与相交面积最大的显示器的交集区域，不先取得整张桌面。采集前后枚举到的其他可见窗口（含桌宠）的遮挡矩形取并集并遮灰；这不是逐像素内容识别，窗口快速变化等边界仍可能影响准确性。
- 近全黑、没有未遮挡有效区域、受保护或无法读取的画面均本地跳过，不调用模型、不触发主动反馈。不尝试绕过受保护内容，也未声称支持安全桌面、受保护视频或独占全屏采集。

## 黑屏及返回面板预览修复

原先通过 Qt 的 HWND 窗口 DC 读取画面，部分硬件加速窗口会返回全黑。前轮改用 Windows `GetDC(NULL)`，只复制目标窗口的物理边界与一个显示器的交集区域，并遮蔽其他窗口的遮挡范围；没有先截整桌再裁剪。采集时短暂切换线程到 PMv2 DPI 上下文，结束后恢复；GDI 写入完成经 `GdiFlush` 后复制到独立 `QImage`，随后释放原生资源。

黑屏质量检查排除遮灰区域，仅检查实际可见的目标像素，避免亮色遮挡或灰块把全黑目标误判为有效画面。近全黑会给出本地不可用原因，不向模型发送。普通深色内容、正常色块及少量细节的边界由回归覆盖，规则仍是轻量启发式检测。

返回 AURA 不会清掉最近一次已通过过滤的预览，而是显示“上次有效观察”标记与跳过原因；自身窗口不截图、不外发，也不重置变化基线。自动模型回复到达时已切回 AURA，则保留可查看的安全预览、不触发过时动作，回到原应用后也不会因查看面板而重复分析。R3 的手动评论是明确请求分析缓存安全预览的例外，可在 AURA 等待反馈。敏感、排除、未知或采集不可用的其他窗口仍清除旧画面和标题；禁用、保存新参数或清空会话也会移除保留预览。

R2 修复了手动倒计时和自动观察的竞争：`begin_local_observation` 预约手动操作后，自动 `poll` 会直接跳过，不读取窗口、不截图、不发起新的 HTTP 请求。完成或取消预约会恢复轮询，不更改用户保存的开关、请求间隔或已有分析状态。版本标识同时加入标题栏和面板右上角，便于核对运行实例。

## 故障排查

| 现象 | 检查方法 |
| --- | --- |
| 无法确认是否运行新版 | 查看面板右上角“会话与记忆版 R7”和标题栏 `2026.10.30-r7`；没有该标记时退出旧实例，再从当前仓库启动。 |
| 没有预览或主动说话 | 确认本地观察已勾选并保存；点击“3 秒后本地观察”后，及时切到目标应用，等采集后再返回面板。持续停留在 AURA 面板、命中隐私关键词或用户无输入过久都会跳过。 |
| 返回面板后提示上次预览 | 这是最近一次通过隐私过滤的画面，不是面板实时截图；AURA 在前台时不会观察自身。需要更新时重新倒计时并切换到目标应用。 |
| 有本地预览但没有 API 请求 | 手动“3 秒后本地观察”不会发请求；自动分析需远程允许、画面变化、超过分析间隔且没有正在聊天。需要立即测试时，检查安全预览后点击“评论当前画面”。 |
| 文本聊天成功但图片分析失败 | 确认同一模型和端点支持 `chat/completions` 的 `image_url` 图片输入；文字模型不能用文本连接测试证明视觉能力。 |
| 有分析事件但没有气泡 | 先看分类、候选评论及中文原因；`none` 表示没有有效可互动情境，空候选回复也不能说话。普通视频可选“陪伴评论”并保存；有效评论仍受低置信度、用户操作、去重、180 秒默认冷却和每小时默认 6 次限制。 |
| 想立即听一句评论 | 启用并保存本地观察及远程发送；取得安全预览后，在原应用或 AURA 前台点击“评论当前画面”。此按钮发起真实 API 请求，不会新截图，也不消耗自动评论额度。 |
| 手动评论按钮不可用或结果被丢弃 | 检查已保存权限、是否有安全预览、是否正在请求/聊天/拖动。切到其他应用、隐私或未知窗口后需重新取得安全预览；API 错误会明确显示，不会用固定台词冒充评论。 |
| 预览黑屏或截图失败 | 已使用可见窗口区域采集兼容硬件加速画面；近全黑在本地跳过，不调用模型。让目标窗口保持可见后重试；受保护、提权或特殊窗口仍可能无法读取，程序不会绕过限制或改为整桌面截图。 |
| 预览中出现灰块 | 这是其他窗口（含桌宠）遮挡目标的范围，已遮蔽以免混入观察。将遮挡窗口移开后重新采集。 |
| 修改了参数但没有生效 | 面板控件不是即时保存；点击“保存参数”并查看状态和错误提示。 |
| 误过滤普通窗口 | 从关键词/排除列表中调整相关条目，再保存；扩大可观察范围前应确认该应用内容适合发送。 |
