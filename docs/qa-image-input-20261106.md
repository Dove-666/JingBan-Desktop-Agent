# R21 主聊天图片粘贴与拖入

桌面主聊天现在可将粘贴或拖入聊天区的图片加入待发送预览。支持单张 PNG、JPEG、静态 WebP，最多 4 MiB、1600 万像素。原有添加图片按钮继续可用；准备图片不会自动发送消息或调用模型，点击发送才提交本轮图片。

## 实现范围

网页只读取本次事件提供的 `File`，不调用系统剪贴板读取接口，也不能向宿主传入任意本机路径或 URL。纯文字粘贴、拖入保持正常处理，文件拖入会阻止页面导航；聊天区接收图片，侧栏只阻止文件导航。

浏览器文件对象的类型可以为空，见 [W3C File API](https://www.w3.org/TR/FileAPI/)。仅空类型或通用二进制类型、且扩展名明确为受支持图片时，网页以对应类型包装原始字节。宿主仍重新校验真实内容，未知扩展和明确不支持的格式不会因此放行。这是合法文件对象的受控兼容检查，不是 Windows 物理拖放故障的证据。

图片读取、等待回执及宿主后台准备相互交接，避免粘贴后立即发送漏掉图片。每次读取绑定来源会话、文字草稿代次及网页身份；切换、清空或重载会废弃未接收的旧读取。宿主已经接收的图片继续使用原来的单工作线程和会话隔离机制，网页重载不会取消它；清空、删除后的迟到结果不能恢复附件。文字草稿不被图片回调改写。

## 验证记录

后端 24 项检查覆盖真实图片仓库、图片格式与大小、会话和网页身份、回执前忙态、后台线程、原生选图、手动发送的本机 HTTP 和清空后的迟到结果。独立补充一项含八类拒绝输入的检查，确认已有图片、像素、文字草稿和历史消息保持不变。

前端 20 项检查及最终编译网页 25 项实际 Qt/WebChannel/DOM 检查通过。实际 `FileReader` 到真实仓库的图片散列一致；粘贴后同一轮事件立即提交不会产生假消息；多图、超限和不支持格式不会读取或替换原有附件；聊天空白区拖入只发起一次读取和准备。另覆盖旧会话回调、同会话清空、网页重载、旧宿主能力缺失及纯文字事件。
