# 2026-11-06 电脑操作异常状态检查

本轮在真实 `GuiBridge` 实现上，用固定的假子进程 JSONL 回执重现了两个问题：

- 收到“输入操作进行中”后，后续回执格式错误或读取异常进入通用异常分支，新异常可能被标成“尚未派发”，并丢失待确认标记。下一项输入因此可能进入桥接层。
- 同一操作再次读取缓存失败时，原来的“结果未知”状态会被重建异常的默认状态覆盖；缓存本身未重新派发操作，但向上层报告的状态不一致。

这些是假协议事件，不表示测试真的点击了桌面。修改前七项新增仓库检查产生九个失败断言；原始失败、独立复现及相应源码散列均保留。

修复只改桥接层：异常出口统一保留当前派发状态，并累积尚未确认的输入；缓存同时保留固定错误码和原始派发状态。同一操作身份继续返回历史结果，不重放输入，也不改变当前其它操作的状态。已确认的输入不会被无差别改成未知；输入前的失败仍明确为未派发。

已有与新增桥接检查共 22 项通过。另一个独立检查覆盖旧未知失败、可信的新只读核验、再次读取旧缓存、随后又有新的未知操作的组合；旧缓存既不污染新核验结果，也不清除当前待确认状态。传统无操作 ID 调用的异常、固定错误码和清理也单独核对。

另用实际 SDK、任务循环和实际 `GuiBridge` 联调，仅替换桌面子进程的 JSONL 传输：运行中输入回执后的格式错误保留 desktop 未知状态；第二个新输入意图由实际台账拒绝；独立文件读取和只读窗口观察仍可完成。两次父级只读核验没有消除未知状态，最终为 `needs_user`。两个假桌面进程均收到停止并完成等待，宿主测试工作进程自然退出。这条链有 8 次本机脚本规划请求和 1 次本机脚本验收请求，真实模型调用为 0。

同批六个场景实际为 **4 项正常通过、2 项明确的预期失败**，后者是仍未实现的纯文件恢复能力，不能算修复成功。[最终联调报告](../artifacts/user-testing-20261105/gui-effect-offline-final-v2-review.json)还保留最初五项测试因公开分词资源 DNS 被阻断的记录，以及首次联调在清理之前错误取计数导致的一项失败。后续使用已有、散列核验通过的公开离线资源；未联网下载或修改用户缓存。常规测试只有一套五场景类和一个实际桥接联调用例，历史夹具字节另行归档；缺少本地 SDK 或核验资源时明确跳过，不自动下载。

本轮没有改动原始目标验收、授权、效果台账、自动重试或任意代码执行开关。纯文件任务在一次可选桌面观察失败后恢复完成的范围仍待解决；不能为了消除这类阻塞，直接解除混合桌面与文件任务的电脑结果核验。

后续范围与仍未实现的条件单独记录在[目标范围设计](AGENT_GOAL_SCOPE_DESIGN.md)，当前未据此增加模式或放宽完成条件。
