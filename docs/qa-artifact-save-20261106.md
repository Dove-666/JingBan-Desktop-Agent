# 2026-11-06 文件保存体验检查

本轮修复文件交付卡片的两个实际问题，并减少桌面导出的重复读取。只使用本机临时文件、受控聊天状态和本地界面，新增真实模型调用为 0；不把这些检查当作模型完成任务的成功率。

## 文件名和保存回执

Python 按 Unicode 码点限制文件名，旧网页按 UTF-16 长度限制，导致合法的中文与 emoji 长文件名被网页丢弃。网页现与宿主使用相同的 240 码点上限；238 码点、246 个 UTF-16 单元的合法文件名通过实际界面检查。

旧保存动作只返回布尔值，失败提示留在未显示的原生状态栏。现在保存动作区分成功、取消和失败：成功显示“已保存”，取消安静恢复，失败显示固定提示并允许重试。不会把路径、原始异常或密钥送入网页提示。旧宿主的布尔回执仍兼容，无法确定原因的旧 `false` 不被冒充为成功或失败。

## 导出读取次数

此前桌面导出复用分页协议，每取 256 KiB 就重新读取、校验整份文件。16,777,215 字节样本需读取 64 次、累计 1,073,741,760 字节。本轮增加仅供桌面宿主使用的单次有界校验快照，随后写入目标同目录临时文件，核对大小与写入时哈希、刷新后再原子替换。

同一样本的真实文件仓库与控制器测试，源文件读取从 64 次变为 1 次，累计读取变为 16,777,215 字节；这两次本机受控运行的耗时分别约 837 ms 与 55.8 ms，不能视为通用性能倍数。没有增加共享内容缓存，手机分页仍对每次请求重新校验。快照存在但校验失败时不会回退分页重试。

空文件、16 MiB 边界、过大文件、错误会话或引用、源副本损坏、元数据不匹配、保存期间会话变化、退出、磁盘错误和旧自定义宿主兼容，均在针对性检查中覆盖。已有目标在替换前失败时保持原字节，临时文件清理单独核对。
