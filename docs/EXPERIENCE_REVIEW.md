# 日常使用可靠性审阅

审阅日期：2026-10-30。以下依据本轮开始时的 R7 源码快照，不代表已完成生产桌面的人工验收。没有读取生产配置、系统凭据或实际屏幕；本轮增量实现与最终测试结果应以交付记录为准。

## 1. P0：关闭权限必须立即生效

**源码证据**：原 `desktop_pet/ui/perception_panel.py` 的 `_enabled_toggled()` 只取消本地倒计时，`_confirm_remote(False)` 只刷新按钮；直到 `_save()` 才调用控制器 `update_settings()`。原控制器又是先保存、再替换实际权限。用户看到开关已经关闭，定时观察却仍可能按旧设置进行；磁盘写入失败也可能继续使用旧授权。

**具体改动**：控制器增加 `revoke_permissions()`，先更新运行时拒绝状态、取消正在进行的分析、清除预览和待显示气泡引用，再尝试保存。取消勾选直接调用该接口；授权仍须用户确认远程发送并成功保存。保存失败明确区分“本次运行保持关闭”与“下次启动仍需检查”，不得把未持久化说成已保存。信号同步不能触发新的保存，撤权不能丢掉其它参数草稿。

**可测场景**：分析请求进行时取消勾选；模拟磁盘拒绝写入；请求在撤权后才返回；撤权后再次保存；托盘暂停/恢复不能重新授予已撤销权限；设置同步不弹授权框、不重复写入。对应自动化用例在 `tests/test_perception_permissions.py`。

**本轮状态**：已增量实现上述接口和界面行为，保留现有运行时 `paused` 接口；采用合成画面和假存储验证，不向外部服务发送图片。新增 11 项权限用例；与感知 UI、核心、集成、评论及持久化屏幕会话链路一同运行，128 项测试全部通过（17.935 秒）。这不代表真实多屏、物理鼠标或外部图片 API 的人工验收。

## 2. P1：退出清理应具备异常兜底

**源码证据**：`desktop_pet/application_controller.py` 的 `shutdown()` 先设置 `_shutting_down=True`，随后顺序调用各控制器清理，末尾才关闭桌宠、发出 `finished`。任何清理异常都可能跳过后续步骤；再次调用又会被幂等标记拦住。`desktop_pet/app.py` 明确设置 `setQuitOnLastWindowClosed(False)`，所以退出不能仅依赖最后一个窗口消失。现有 API 客户端已经支持异步任务取消，Mem0 也有辅助进程终止机制，应该复用。

**具体改动**：各子组件独立执行受控清理，窗口、气泡和托盘的收尾即使某项失败也继续；总的退出信号放在保证执行的最终路径。保留已经接受的数据库写入，避免 GUI 线程无限等待；不要在普通日志输出原始后端异常或密钥。单实例锁的释放也应在最终路径。

**可测场景**：注入一个抛异常的 `shutdown()`，确认其余控制器仍被清理、退出信号恰好一次；请求和标题生成进行时退出；随后立即重新启动，验证不会被失联实例锁住。此项是静态风险判断，审阅时未人为制造生产进程异常。

## 3. P1：面板应在小屏和移除显示器后保持可达

**源码证据**：原 `desktop_pet/ui/debug_panel.py` 为调试窗口指定 730×740、最小 620×580，为聊天窗口指定 920×720、最小 660×520；`desktop_pet/ui/memory_panel.py` 指定 700×700、最小 590×500。原 `_HideOnCloseWindow.present()` 只执行 show/raise/activate，没有按当前工作区重新检查位置。桌宠自身已处理 `screenRemoved` 和工作区变化，但独立面板没有对应恢复路径。

**具体改动**：复用统一窗口放置服务，在恢复、显示、屏幕移除和工作区缩小时检查窗口与可用区域交集。保留标题栏和主要操作可达；小工作区允许降低固定最小尺寸并让内容滚动。使用 Qt 逻辑坐标，不把不同 DPI 显示器的物理坐标直接混算。

**可测场景**：模拟 800×500 工作区；在第二显示器打开聊天后移除该屏；屏幕排列含负坐标；DPI 改变后恢复窗口。自动化几何测试应明确区别于尚未进行的真实多显示器人工测试。

## 4. P2：记住位置，同时防止恢复到屏幕外

**源码证据**：原 `desktop_pet/pet_window.py` 启动时固定在主屏右下角，`moveEvent()` 只重定位气泡；原 `SettingsManager` 只保存角色缩放，没有窗口位置/大小接口。用户每次重启都需要重新摆放角色和聊天面板。

**具体改动**：保存桌宠位置和各独立面板几何，使用单独、非敏感的设置键；拖动时去抖写入，关闭时刷新最后一次值。恢复前验证数据类型、范围和显示器可用性，失效时回退到当前工作区；角色大小继续由原缩放逻辑决定，不用恢复的窗口尺寸覆盖角色控制设置。

**可测场景**：保存位置后新建测试控制器恢复；损坏和极端坐标安全回退；改缩放后位置仍可达；写入失败不阻止桌宠启动或退出；没有访问真实用户设置。

## 5. P2：提供稳定的托盘救援和隐私入口

**源码证据**：原桌宠采用 Tool、无边框、不接受焦点的窗口标志，主要入口在角色的右键菜单；调试与聊天窗口关闭时只是隐藏。已存在的重复启动唤醒机制能作为救援，但缺少日常可见的常驻入口。

**具体改动**：使用轻量 `QSystemTrayIcon`，提供显示桌宠、聊天、调试、长期记忆、暂停感知和退出。只有托盘实际可用时才允许用户隐藏角色；没有托盘时保留角色入口。暂停是运行时状态，不应悄悄授予或清除保存的远程授权；恢复后仍尊重权限撤销。通知区图标与菜单应跟随实际状态更新。

**可测场景**：托盘不可用时禁止隐藏导致失联；隐藏后点击图标或菜单恢复；暂停期间没有观察/分析；恢复不会越过已撤销的权限；退出销毁托盘。原生通知区点击仍需独立环境验收，不能以 QAction 单元测试代替。
