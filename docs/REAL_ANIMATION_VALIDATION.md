# 真实序列帧播放验证

`tests/real_animation_smoke.py` 用临时 INI 和内存凭据构造真实 `ApplicationController`，在 Qt offscreen 平台运行。它只渲染自己的控件，只向自己的窗口发送 Qt 鼠标事件；不读取桌面，不使用物理鼠标，不操作已经运行的桌宠，不创建或修改产品帧。

脚本需在真实视频经过 SAM2、规范化和视觉验收，发布完整目录后执行。`complete`、`qa_passed` 必须显式为 `true`，`origin.synthetic` 必须显式为 `false`。测试图片或未审核的草稿不能作为真实动作验收。

```powershell
.\.venv\Scripts\python.exe -m tests.real_animation_smoke `
  --directory assets/character/animations `
  --names think_scratch_head snarl_cute `
  --expect-frames 62 `
  --output artifacts/character_assets_real_v1/real_playback
```

也可只给一个已就绪的动作名称。`--directory` 是包含动作子目录的父目录。脚本的历史默认值仍为 60，**本批真实交付为每段 62 帧，必须显式传入 `--expect-frames 62`**；不能为了通过检查而删减原始处理证据。

脚本输出 `result.json` 及每个动作播放中、200% 大小和结束状态的控件截图，检查：

- 后台加载真实全部帧，当前帧与缓存数量符合清单。
- 正常播放时不重新加载文件、不重新执行图片布局与缩放。
- Qt 鼠标拖动会移动自己的窗口，拖动时帧时钟和程序动作冻结；释放后先平滑恢复，再继续播放。
- 六档缩放保持画布比例和可见边界；拖动中停止延迟至释放后恢复，停止清除逻辑缓存并还原已选静态角色。
- `idle`、`hold_last` 或 `loop` 按清单实际执行；重复播放仍可完成。
- PNG、清单和原始 `whale.png` 的哈希不变。

每个阶段记录 GUI 16ms 心跳的次数、最大间隔和 P95 间隔、CPU 时间、当前工作集、峰值工作集及私有内存。最大心跳间隔超过 2 秒会失败；这个阈值用于发现严重阻塞，不代表低于阈值就已经达到所有机器上的流畅标准。正常播放的心跳、CPU 和缩放耗时应结合实际机器评估。

## 内存预算

1024×1024 的解码 RGBA 帧每张占 4 MiB。本批每段 62 帧，原始解码数据为 **248 MiB**；播放器目前最多接收 96 帧，对应 **384 MiB** 原始解码数据。上限只约束一组活动素材的原始帧数，**不是进程内存上限**。

播放器另保留当前窗口尺寸的 QImage 与 QPixmap 缓存。以本批 62 帧为例：

| 缩放后画布 | 一份缩放缓存的像素数据 |
| --- | ---: |
| 305×305（本轮默认尺寸实测） | 约 22.0 MiB |
| 531×531（本轮离屏 800 高工作区中的 200% 实测） | 约 66.7 MiB |
| 610×610（有足够工作区时的 200%，理论值） | 约 88.0 MiB |

具体画布取决于显示器工作区。Qt 后端可能共享 QImage/QPixmap 数据，也可能额外分配原生绘图缓存；解码临时缓冲、进程基线、窗口和 Python 对象还需额外内存。本轮进程峰值 RSS 实测为 **496.52 MiB**，正常播放约 400 MiB；原生源帧留作素材档案，不应与游戏帧一同加载到播放器。

只有一组素材可同时后台加载；重复点击不会无限排队。停止会释放程序对活动帧和缩放缓存的引用，但 Qt、操作系统或内存分配器可以保留已经分配的页，RSS 不保证立刻降到初始值。脚本同时报告逻辑缓存清理与实际工作集，不能只凭 RSS 没有立即下降判断泄漏。

本批虽然在生成界面选择 5 秒，两个真实文件均实际为 124 帧、24 FPS、约 5.166667 秒。SAM2 处理全部 124 个原生帧后，再按时间戳选择 12 FPS 的 62 个交付帧；清单的播放时长为 5167ms（精确计算值为 5.166666… 秒）。`origin` 保留原始帧率、全部分割帧数、交付帧率、源帧索引及采样策略。不能据界面选择值强行写成 60 帧，也不能把重采样说成保留全部原生播放帧。

后台负责文件读取、解码和透明度检查。首次安装素材及用户缩放时，GUI 仍需一次性创建缩放缓存；播放中的切帧才是直接交换缓存。离屏报告会记录这次 GUI 工作的实际延迟，不能宣称整个加载过程完全没有 GUI 处理。

## 本轮真实执行结果

上述命令已经对正式发布的两段真实资产运行成功。完整报告与控件截图位于 [real_playback](../artifacts/character_assets_real_v1/real_playback/result.json)。本轮使用临时配置、内存凭据和离屏实例；没有操作用户正在运行的桌宠，所有帧、清单与原始 `whale.png` 的哈希保持不变。

| 实测项目 | 思考挠头 `think_scratch_head` | 奶凶呲牙 `snarl_cute` |
| --- | ---: | ---: |
| 实际交付 | 62 帧 / 12 FPS | 62 帧 / 12 FPS |
| 后台加载与安装缓存 | 0.8781 秒 | 0.8876 秒 |
| 稳定播放采样长度 | 0.8920 秒 | 0.8969 秒 |
| 稳定播放 CPU，单核 100% 口径 | 3.50% | 1.74% |
| 稳定播放最大 GUI 心跳间隔 | 18.076ms | 18.452ms |
| 稳定播放 RSS | 400.078 MiB | 400.914 MiB |
| 拖动后时钟、当前帧和程序动作冻结 | 通过 | 通过 |
| 释放后先平滑恢复，再继续切帧 | 通过 | 通过 |
| 50%、75%、100%、125%、150%、200% 比例与边界 | 通过 | 通过 |
| 停止后清除逻辑缓存、恢复选定静态角色 | 通过 | 通过 |
| 完整重播后的结束行为 | 恢复选定静态角色与待机 | 保持真实第 62 帧 |
| 停止后 RSS | 129.668 MiB | 130.078 MiB |

所有被记录阶段中最大心跳间隔为 **31.573ms**（缩放时），没有出现秒级阻塞。CPU 是约 0.9 秒短采样的进程 CPU 时间与墙钟比，单个核心满载记为 100%；后台加载和 Qt 缩放可使用多个核心，因此其数值可超过 100%，不能误写成系统总 CPU 百分比或长期负载结论。

本轮基线 RSS 为 128.648 MiB，200% 缩放等阶段的整体峰值为 496.52 MiB。`hold_last` **保持末帧时仍保留约 400 MiB 的整组缓存**，直到点击停止或切换动作；保持画面不等于释放内存。报告中的 `after_completion` 在显式停止之后采样，不能拿该字段的约 130 MiB 误称末帧保持时的内存。

已目检两动作的真实首尾帧、挠头中间帧的手部和蓝色问号、200% 离屏控件图以及结束画面，未发现播放器造成的裁切或比例异常。完整项目回归另有 **640 项通过，用时 237.607 秒**，见 [测试报告](../artifacts/character_assets_real_v1/unittest_report.json)；该数量不与此前快照重复累加。

另已在本轮新启动的 Windows 原生桌宠实例中实际触发挠头动作，保存的 [原生中间帧截图](../artifacts/character_assets_real_v1/native_pet_think_middle.png)可见手部挠头、蓝色问号及透明背景。原生奶凶动作与物理鼠标拖动结果仍不充分，不能据此宣称通过；两者在上表中的播放与拖动验证指离屏 Qt 事件测试。

## 证据边界

本脚本不验证模型生成的人物身份、动作是否符合提示词、SAM2 发丝/尾巴边缘和特效完整性，也不代替 Windows 实际合成、任务栏、多显示器或物理拖动验收。真实素材的视觉审核和生产来源记录仍由资产流程负责。

本轮真实运行结果以上述报告为准；理论预算已明确标记。离屏成功与原生挠头截图都不能替代尚未确认的原生奶凶播放、任务栏、多显示器和物理拖动验收。
