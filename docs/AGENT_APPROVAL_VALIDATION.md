# Agent 操作权限验证（2026-11-15）

本次仅修改本地源码与内置聊天页面。未提交、推送 GitHub，未重新打包 Windows 或 Android。桌面「鲸伴」快捷方式指向本项目的 Python 启动器，退出后重新启动即可加载改动。

## 实现

- 聊天输入框旁新增「请求批准 / 帮我批准 / 完全访问权限」，默认「帮我批准」；普通聊天隐藏入口，执行中禁用切换。设置页和兼容聊天界面同步同一配置，保留未发送草稿。
- `ask` 在联网、命令及未知工具调用前询问，工作区外写入必须经过 DSH 官方单次提升审批。不能凭模型填写的权限字段直接执行。
- `auto` 使用固定版本的官方 Auto Review，风险操作询问，审查失败拒绝执行。使用同一 API，会增加模型请求；风险判断并非绝对准确。
- `full` 使用官方完全访问模式，自动处理明确的电脑访问授权；普通澄清问题仍显示，已关闭的工具不会被重新开启。
- 原生会话与队列身份包含权限模式；旧模式的授权不能带到另一模式。模型输入中的斜杠命令不能更改宿主选择的权限。
- 批准卡展示与实际调用关联的参数；拒绝、过期、撤回或停止不会因残留答复文本被当作批准。
- 新增模块已纳入现有打包文件选择规则；本次未生成安装包。

## 保留的问题与验证边界

扩大回归失败的是 `test_actual_validation_failure_without_any_launch_must_not_hold_unknown_slot_forever`。该旧夹具删除临时 `python-owned.exe` 并期望零启动，但 HEAD 的运行链早已使用 Node 与 `worker.mjs`；本次 service 仅新增权限模式传参。没有通过更改预期次数掩盖失败，也没有修改该旧测试。现有 DSH 缺失 Node、无启动凭据、队列释放测试通过，但旧夹具的完整 RPC → 修复 → 新任务恢复链仍需迁移。

权限参数显示测试中间曾有两项失败，原因是 SDK 参数已序列化，再次序列化导致双重转义。修复后相关批准/拒绝及最终 SDK 回归通过。

SDK 集成的负向名称筛选未排除既有 Windows 应用枚举测试，因此实际运行了只读应用枚举和原生助手关闭检查；没有前台点击或键盘输入。未验证真人模型的风险判断质量、手机实机或新安装包。三档权限均不构成操作系统隔离，仍受 Windows 权限、UAC、功能开关和停止机制限制。
